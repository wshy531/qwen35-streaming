# 记忆任务对齐与证据审核结果

2026年10月19日。本段完成现有任务覆盖审计、13道真实情景记忆题的完整采样前缀复核、同一自然事件的延迟诊断草案，以及新24源72题的元数据候选安排。没有加载模型、生成答案、使用GPU、连接集群或下载新视频；旧综合汇报未改。

## 为什么先做这个？

短期记忆要服务最近动作与细节，长期记忆要保留近期窗口之外、回答时仍有用的证据。此前主要比较集更偏一般视频问答；视频长、证据标在早期，并不自动代表题目必须依靠长期记忆。

本地StreamForest笔记将current/short/past任务绑定查询时刻，DrVideo笔记区分“是否找到了证据”与“证据能否被读懂”。本段把这些思路落实到证据账本与控制输入，没有新增网络模块，也没有声称复现了论文训练效果。

## 1．现有121道自然题覆盖什么？

公开74题加已打开的留出47题，共121题、45个规范视频ID。本次只对这些题做元数据覆盖审计，没有把它们重新包装成未见集。

按作者区间最后结束时刻至提问的距离：0—10秒67题、10—30秒28题、30—60秒20题、超过60秒3题，另3题未知。F/T层中有25题满足距离至少16秒，已列出准确题号，**完整前缀重复证据审核仍待完成**。这些数字只能说明证据距离代理，不能代替旧记忆必要性验证。

## 2．最贴近记忆目标的原EPM题，为什么没有进入主测试？

原候选19道EPM情景记忆题中，13题来自6个真实Ego视频文件，但尚未核清它们对应的父录制；6题来自模拟场景。它们没有进入后来的自然主比较。此前有少量开发题实际跑过，并不是从来没有测过。

这次完整复核了6个真实文件在原查询前的共同0.5FPS输入，共929个原256×192画面、60页图。每个画面都绑定真实帧号、PTS和像素指纹，没有只挑作者答案附近几张图。对较早查询，后续页中的未来帧不作为该题证据。

13题中6题有可用的原画布支持，7题仍有物体不清、动作截止边界或选项歧义。6题中5题的直接证据就在近期，例如：

- 视频已播放约七分钟，但粉色毛巾擦手发生在408—410秒，查询411秒。
- 从塑料袋拿洋葱发生在272—278秒，查询278秒。
- 打开扳手抽屉发生在402—410秒，查询411秒。

它们能做近期感知对照，不能因为视频长就称为长期回忆。

唯一更直接涉及多事件累计的是“盛了几次水泥”：在190—248秒可见五个盛取/倒出循环，早三轮不在约32秒近期窗口内。不过最后模具上堆积的材料可能提示次数，仍需排除末端画面的捷径。

这还暴露了单一距离指标的不足：计数题最后一次动作离提问很近，**但答案可能需要累积更早的多次动作**。以后应同时记录全部支持事件，而不是只用最后区间的距离判断短期或长期。

7道未决题均保留原标签。例如“beside the trashcan”和“beside the dustbin”是同义选项，不能用某次模型恰好选中官方字母来证明唯一答案。另有被遮挡的放盆动作和难辨认的微小物件，没有强行补证。

父录制未核清的问题没有被解除。**内容支持6题，不等于正式准入6题；这一组仍然只是来源未完全核清的机制诊断材料。**

## 3．做成了什么可执行的诊断草案？

以已确认的洋葱取物事件为例，新建了一个明确锚定约274秒事件的问题，询问它取出前所在的容器。新问题和选项在三个查询时刻完全相同：

| 查询时刻 | 相对近时查询的延迟 | 中间输入 |
|---|---:|---|
| 278秒 | 0秒 | 取出洋葱后的画面 |
| 342秒 | 64秒 | 原视频继续剥切与处理食材 |
| 472秒 | 194秒 | 原视频继续存放、烹饪和取锅具 |

没有重复片段来填长，没有跨视频拼接；只延后提问并保留自然发生的中间活动。它是**新编的时间锚定诊断题**，不是原官方题，也不是3个独立样本。明确的时间锚定也不能冒充自动语义检索。

6道内容支持原题，加3个延迟版本，构成9个诊断案例。其中3个版本共享同一个洋葱事件。为它们预先建立42个输入条件：完整前缀、最近8对、纯文字、人工相关证据；对于确有旧证据的情况，再加移除相关旧帧对及等数量移除其他旧帧对。

人工相关证据是诊断参照，不是候选自动选择结果。移除实验保留完整原帧对和时间，不把剩余帧重新配成别的对；两种移除保持近期输入相同。移除后的原选择题没有“证据不足”选项，因此原标签只能用来观察回答敏感性，不能把某个改答案直接当成规范的遗忘分数或充分因果证明。

42是输入条件数，不是42道独立题。原19题未改；原题、衍生题、人工证据和移除条件均有独立身份。

## 4．目前核验到哪一步？

929个PNG画面区域逐一裁出，像素SHA与实际解码回执相同；19原题身份与原始候选逐条一致。42草案的源帧身份、截止时间、原配对及移除数量均通过检查。

实际0.8B分词器容量检查通过：最大6946输入Token、69后缀Token、119个帧对、5712视觉Token，落在原完整参考8192/6144/128额度内。这里共同采样为0.5FPS，近期8对约32秒，不能与旧1FPS成绩直接混合。

**仍未完成选择性帧对的模型读入适配、CPU位置/像素接口检查及GPU执行冻结。** 本段没有生成任何新答案，旧证据是否必要、原模型是否能读懂这些证据、记忆候选是否有收益，都还不能作结论。

本段图像73,143,896字节，低于事前120MiB上限；解码和渲染约458.8秒。未使用额外原分辨率追图额度，没有保存大型特征张量。

## 5．新独立来源已安排到什么程度？

从现有官方GQA标注排除本项目登记的60个源后，还有507个有可用标注的规范视频ID。本段用固定哈希次序筛出24个新来源、每源3道原题，共72题，尚未下载或看图：

- 视频64—131秒，包含2段至少120秒的视频。
- 23个源的历史目标题，其作者证据距提问至少60秒；另1个至少30秒。
- 原任务类型为TN29、TC19、CH14、TP1、CW9，尚未经人工重新分层。
- 20个源有距离不超过10秒的最近可用题，另4个不能假称已具备严格近期对照。
- 全部规范ID均未出现在本项目登记100媒体中；不同拍摄场次和预训练污染仍未保证，实际重复筛查待下载后完成。

官方ZIP目录中对应24个MP4的总字节为212,445,996，约202.6MiB。已保存准确路径、原题号、大小、作者CRC和获取草案；此前使用的第三方镜像在固定revision上的每文件SHA仍需重新取得，不能套用旧60文件的回执。获取建议上限256MiB、45分钟、GPU0，仅取所需24文件，不下载完整压缩包。

这是一份**具体元数据候选清单，不是已经构建完成的72题测试集**。后续必须经过媒体校验、完整采样前缀审核、重复证据检查和明确的必要性控制，失败题继续保留，不能按模型正确与否决定准入。

## 6．下一步的有界顺序

1. 先对42条件草案完成保留原帧对编号与时间的CPU读入适配，固定一次诊断的生成与资源预算；执行后分开分析基础读不懂、近期能代答和旧证据有影响，不反复修改这一个洋葱案例追分。
2. 新24源72题按已固定清单获取和审核，作为后续候选的新验证来源；没有合格视频和证据前不冻结，也不保证最终仍有72道准入题。既有25个早期F/T题仍可作开放回归补充，不能当成新未见测试。
3. W3问题相关读取仍在队列中，但先过上述任务对齐门槛。之后只选一个本地文献支持的读取适配，使用既有开发数据固定方案，再在新来源准入清单上比较，避免继续用当前题评价不匹配的能力。

这段工作的作用是把“长期记忆为什么没涨分”拆成可检查的任务和证据问题；它没有优化模型，也没有完成新的正式长期记忆基准。
