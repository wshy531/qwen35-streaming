## 本阶段做了什么

1. 为原模型与记忆候选建立相同原视频、问题选项、因果采样前缀和评分边界。完整问题不截成64Token，完整历史参考不冒充八对窗口；奇数尾帧只在本次查询快照补齐，不能写成下一段已到达的真实帧。
2. 比较最近窗口、四近期加四长期完整代表、真实特征森林以及CausalMem式原Token选择。Token上限与额外语义基载荷分别计量，保留基础不可答、格式错误和新增损失。
3. 新增问题相关读取Q4：M1银行最多保存384视觉Token，最终回答读取192；固定最近两对，再按原问题条件似然选旧两对。评分不读取选项、正确答案或作者证据区间，查询不改银行。它没有训练，也不是特征压缩。最多六次额外评分需要另计成本。
4. 审核新24视频/72原题，完整检查固定采样前缀50页；50有视觉支持、22歧义保留。纳入22视频/21保守场景组，事实21+时序24为主，动机解释5为次。不能把审核支持说成必须使用旧记忆，亦无第二人独立复核。

## 结果与决定

以下是新来源复验中的严格单字母答对题数。原生完整/完整pair采用相同低分辨率0.5FPS画面，不是基座默认高分辨率效果。最终192Token几种读取同预算，完整参考和全部M1额度更大。

| 路径 | 新50题 | 主事实/时序45题 |
|---|---:|---:|
| 原生完整视频 / 完整pair | 15 / 15 | 12 / 12 |
| M1全部八对，384Token | 22 | 19 |
| 最近四对，192Token | 27 | 23 |
| 均匀四对，192Token | 25 | 21 |
| Q4问题相关四对，192Token | 22 | 18 |
| 作者区间引导四对，仅诊断 | 22 | 19 |
| 纯文字 | 19 | 17 |

Q4对均匀有3纠正、6新增错误；多用82.48秒评分，没有形成收益，**不升级默认**。原生与完整pair的50条生成Token一致，两者16格式错误；首选项诊断均23/50。因此不能把严格15到22说成新增视觉识别能力。旧开发24、公开74、已打开47的Q4为16/24、40/74、25/47，不以其中局部成功代替新来源复验。

十道采样中未见后期重复的早期题，八道作者相关时段的实际画面在M1就没留下。M1来源节点范围可以覆盖第0—15对，真实代表却仅第0对；范围记录不等于完整内容。另有已保存却被Q4舍弃，以及选到相关时段仍答错的情况。这些标记有重叠，作者区间亦非必要充分证据，不能硬分成互斥因果错误。结论仅针对当前M1对照，不冒充语义森林失败。

下一段先补已打开25早期F/T内容审核，再固定读取器、比较同384Token短事件保护；新50已打开，不继续当未见留出调参。进一步独立来源需另行准备和冻结，本PR不宣称已完成该实验。

## 一个活动源码入口

`src/` 中四个文件保持实验原字节，来源与SHA见 [SOURCE_MAP.json](SOURCE_MAP.json)：

- `memory_policy.py`：有界近期与时间层级代表；不把层级范围当保存全部证据。

- `selector.py`：Q4评分与选择；不自动加载模型或升级默认。

W1/W2/W3的完整实验驱动、CausalMem式银行、森林384适配、数据审核与全部原答在下述归档中，保留原文件路径与源码SHA，避免另建多份可编辑核心副本。原模型与流式核心继续使用仓库原有目录；[依赖身份](REPOSITORY_DEPENDENCIES.json)复核这些文件与历史运行时的SHA一致。
