# 流式架构改动通俗讲解

说明日期：2026-10-12。依据当前活动源码与已登记的历史实验；本次只有源码检查和文档整理，没有新的GPU运行。本文是机制解释，持续进度与未来计划只见《实验总纲.md》。

## 1. 同样回答，为什么还有作用？

这次主要改变的是“视频到达后如何计算、内部状态如何接续、什么时候能提问”，没有训练新的识别知识。把一次看完视频再回答的调用方式，改成画面陆续到达、状态不断更新、中途可以提问的会话，同一段已看到的画面仍应给出相近答案。同答是有限正确性控制，不是无用的证明，也不是能力提升的证明。

例如第2帧时提问只能使用前2帧，第4帧到达后接续前面的状态再提问。常见的离线重复调用会重新提交前2帧、前4帧、前6帧；我们的主路径每次只把新增的一对帧写入模型。原模型本来就有缓存，我们没有发明KV cache；我们修正了这个混合模型的多Token缓存续接，并建立视频会话的读写规则。

同输入同答本身证据有限。我们还分别检查过固定FP32样例的内部状态与数值、问答后主状态不变以及reset重新开始。BF16和独立整段/分块视觉数值等失败仍保留，不能宣称任意输入全部等价。

## 2. 核心改动一：接续模型的混合状态

Qwen3.5-0.8B的24层语言网络中，6层使用注意力，18层使用Gated DeltaNet。它不能只保存一种缓存：

| 状态 | 通俗理解 | 新块到来时的作用 |
|---|---|---|
| 注意力K/V | 可供后续注意力查询的旧Token记录 | 新Token可以利用之前输入 |
| 卷积状态 | 邻近输入的短期缓冲 | 块边界处的卷积仍接得到前面的上下文 |
| 递归状态 | 随处理过程不断更新的内部工作状态 | 后面的块从上一步状态继续计算 |

递归状态不是可直接阅读、保证可靠的语义摘要。“模型里还留着状态”不等于“模型能正确回答过去事件”。

原实现的缓存复用路径主要按单Token续接处理；一段视频通常带来多个Token。我们修改Gated DeltaNet的多Token路径，使卷积使用前面的缓冲、递归运算接收之前的initial_state，再写回新状态。另加完整缓存clone/reset，覆盖K/V、卷积、递归四个张量列表。这是涉及模型内部的实质改动，网络层数和训练权重没有改变。

源码：活动实现中的`qwen35_local/modeling_qwen3_5.py`。

## 3. 核心改动二：建立连续写入的会话

`HybridSequence`管理缓存、已处理Token数、位置编码和容量。固定提示前缀写入一次，新视频块只追加新的嵌入。旧Token不重新作为完整前缀送入语言网络；但注意力仍会查询旧KV，所以不是后续计算完全与历史长度无关。

位置相当于书签和坐标：后面一块不能又从第0页开始。视频还需要时间、高度、宽度等位置；位置计数、缓存长度与因果遮罩必须对应。视频时间戳也按协议放入输入，我们没有另行训练新的时间编码器。

当前视觉处理要求成对帧：该模型的时间patch为2，所以先等到两帧，再编码这两帧并写入主状态。不是所有视频模型都必须两帧一组。文件结尾若只剩一帧，显式复制用于补齐编码，不冒充又收到了一帧真实画面。

源码：`streaming/hybrid.py`、`streaming/online.py`。

## 4. 核心改动三：把观察和回答分开

```text
新画面 → 成对视觉编码 → 视频主状态S → 接续下批画面
                              │
                              └─复制状态 → 写入问题 → 生成回答 → 丢弃问答分支
```

问答使用主状态的完整缓存副本，模型权重共享，并不复制整套0.8B权重。生成的问题和答案不会写回视频主历史。如果模型答错“这是猫”，后面的观察不会把这句话当成已经接收的历史输入。

隔离也不意味着自动拥有聊天记忆：当前问题需要自包含，不能默认下一次知道上一次用户问了什么。这里学习的是状态所有权、分支以及副作用控制。

## 5. 有限容量、reset与持续输入

历史Token有预算，还要为问题和回答预留空间。容量不足时重置全部混合状态，重新建立前缀，再接收新画面。界面显示当前记忆起点，视频总时间和帧编号仍向前推进。

这是有界流式会话，不是无限记忆。程序可以持续接收画面，但reset前的主状态历史已经丢失。只剪掉旧KV也不能同步擦除递归状态里的历史，因此不能直接套用普通Transformer的KV裁剪。

墙钟播放入口使用有界最新帧槽：推理慢时替换尚未被消费的采样帧，记录丢帧；不在队列里无限积压，也不取消正在执行的模型计算。视频时间、模型实际处理到的时间、回答出现的时刻分别记录。成对帧之间的时间间隔可能因丢帧而增大。

## 6. 哪些是工程支持，哪些是可选探索？

| 项目 | 用途与边界 |
|---|---|
| 通用视频入口、自定义问题、采样率与时长 | 从固定23帧选择题复现脚本，扩展为能换素材的问题入口 |
| 等比缩放补边 | 避免横屏/竖屏被拉伸；属于输入处理 |
| 画面、时间戳、回答与重置显示 | 让用户看清系统当前看到什么、还能参考多久以前的输入 |
| full/last/none logits | 视频写入只更新状态，不做无用的词表输出；问答只取末位置输出，完整输出保留给回归。不等于Token压缩 |
| FP32参考与32/64计算块探索 | 帮助控制数值和研究计算实现；计算块32不是视频窗口32，不是删掉Token。默认64参考保持 |
| 时间索引真实帧记忆候选 | 独立CPU保存少量旧画面；按明确时间取回到独立问答分支，可跨主状态reset提供旧证据。尚未接为默认产品入口 |

时间记忆候选按固定间隔保存真实成对帧，最多3对、6帧，像素缓冲上限864KiB，另有小量元数据；先进先出淘汰。没有保存的时间明确表示无证据，不凭空补画面。它不是记忆森林、语义检索、模型记住全部过去或Token压缩。取回正确画面后仍可能识别错误，留存、检索和理解须分开验证。

## 7. 学习目标与下一步

目前建立的是“固定预训练基座＋混合状态多Token续接＋增量视觉协议＋隔离问答＋有界重置与输入调度”的原型。不是重新训练的更聪明模型，也不是提出全新的基础网络。它展示了从离线模型建立流式会话必须解决的接口和内部状态问题。

下一段先用4–6帧演示状态轨迹：输入前缀→追加首对→提问复制→主状态不变→追加次对→重置。先能解释每一步，再选跨重置旧证据等具体问题做一个最小架构实验。性能只作为资源与计算行为的辅助证据，初期不把提速或提高准确率当成必须达成的门槛；训练、压缩、森林没有默认加入的要求。
