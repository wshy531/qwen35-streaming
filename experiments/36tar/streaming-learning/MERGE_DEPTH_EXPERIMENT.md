## 为什么这一步比前一轮多了一项证据

上一轮只把两对动物画面压成一个旧根，没有发生跨闭组长期合并。本轮一方面主动把动物旧根与后来的洗手片段逐级合并；另一方面让原森林按预算真正做一次在线跨段合并。

人为每2对切段的银行有如下过程：动物0–1对→洗手2–3对→洗手4–5对→后段6–7对。闭组预算只允许96Token，于是第6对到达时，原三项代价选择合并0–1动物根与2–3洗手根，得到0–3根。两条视频各实际发生1次long merge，最终根范围为0–3、4–5、6、7，仍在192视觉Token上限。

这样合并后，问开头动物，狗答dog、猫答cat，两条都正确。它证明这次跨不同内容片段的合并之后，粗主体仍可读取。每2对切段是人为诊断规则，不能声称模型自动发现了4个自然事件。

原自动分组银行本轮保留0–1、2–5、6、7，没有触发long merge；其原/packed读取也都正确。因此不能把强制合并日程冒充默认算法的实际选择。

## 合并到底怎样计算

控制梯度把每两对先合为48Token，再从左向右合并这些小根。7对时有2/2/2/1四个控制段，根深度为4。

```python
# 每个节点有 features、mass 和幸存Token的来源坐标
root = merge(pair0, pair1, within=True)       # 96 → 48
root = merge(root, merge(pair2, pair3, within=True))
root = merge(root, merge(pair4, pair5, within=True))
root = merge(root, pair6)                    # 仍48，覆盖7对
```

匹配沿用冻结ToMe式规则：在候选Token之间寻找相似目的位置，再按mass做加权合并；质量一直累计。7对根的mass总和336，来源范围0–6。mass是原Token贡献量，不能理解为识别置信度。

原子张量在候选银行中按预算释放。为了做公平诊断，本轮另有每条最多8对的有限原特征参照池，CPU内存单列；没有把参照池当作生产森林的长期存储。

## 预备的新候选为什么没有做GPU

预登记了一项平衡合并顺序：先并相邻小根，再并上层，把7对根的最大深度从4变为3，旧Token仍48。CPU契约和完整随机模型流程已经覆盖它。

真实启用条件是：某一级未压缩狗/猫配对两条都正确，而对应压缩配对至少一条错误。本轮没有满足条件，因此没有运行这项候选的真实GPU问答，也没有宣称它带来效果。当前真实结果不足以支持改默认合并方式。
