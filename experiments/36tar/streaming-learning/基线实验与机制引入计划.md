## 验收顺序

1. 重跑仓库 3 个随机小模型测试，确认原实现迁移。
2. 小型 CPU 模型比较一次前向与 3→1、2→2、1→3、逐 Token 分块。多 Token 不一致先作为原实现能力边界的诊断，不为得到 PASS 偷改原基线。
3. 自生成单图与 4 帧色块 MP4（1 FPS）；颜色变化和反转序列；验证实际编码/解码以及来源哈希。
4. 从固定官方 revision 只下载 PyTorch 权重、配置/处理器/tokenizer，不下载 ONNX/GGUF 等其他格式。
5. 单卡真实权重文字、单图、3 条 4 帧短视频推理；不同序列独立前向，明确是离线基线。每次最多生成 16 个 Token，总作业上限 10 分钟；必要时先 1 条 smoke 再扩展，失败不自动反复运行全部。

每次独立 run 目录，保存 provenance、status、完整错误及短摘要。已完成病例即时落盘，后续失败时复用预测。峰值 allocated/reserved 分开记录；初版 generation 时间包含 prefill+decode，不把它冒充单独首 Token 或视觉耗时。

色块样例只验证输入绑定、简单颜色/时间任务，不能证明自然视频理解或论文精度。contains_expected 字段仅为方便检索的文本匹配，不是正式准确率；必须人工检查答案是否含混。离线基线会读取全部 4 帧，不能作为在线因果性证据。

## 已有笔记怎样服务后续决策

资料 A：`C:\Users\21195\Desktop\大模型学习`；资料 B：`C:\Users\21195\Desktop\视频实时分析`。本轮全文提取 A 的 KV Cache.pdf（6 页），选读 B 的 StreamForest.md 方法与事件合并部分、Token压缩.md 机制/误区、STC 历史结果，以及 A 的 RoPE 笔记。不把原笔记里的示意参数、代码或旧实验成绩当作 Qwen 基线结果。

| 机制 | 何时考虑 | 必须先拿到的证据 | 主要风险/成本 |
|---|---|---|---|
| 原生 KV + 递归缓存 | 基线生成时使用 | 原仓库小测试、实际 use_cache 和状态形状 | 不能把文字 decode 的续接推断成视频 chunk 续接 |
| 视频增量状态续接 | 原模型短视频输入稳定之后 | 相同输入协议下整段/分块 logits 与混合状态对照 | 同时承接 KV、conv、recurrent；位置和两帧 patch 边界 |
| 有界 KV / 近期窗口 | 连续输入使 KV/延迟增长时 | 随长度的状态字节、耗时、早期事件问答 | 裁剪 KV 不擦除递归历史；截断后的长度不能当累计位置 |
| 简单视觉 Token 池化/合并 | 视觉 Token 导致 LLM 读取成为瓶颈时 | 视觉/LLM 耗时拆分、保持细节的配对样例 | 破坏空间/时间坐标，小目标、计数、顺序退化 |
| ViT 内部缓存复用 / STC 类优化 | 视觉编码确为主要瓶颈且静态冗余高时 | 实际视觉耗时、动态/静态样例、新旧特征误差 | Qwen 视觉时间 patch、位置及上游依赖不同；不能直接复制旧 patch |
| 差分丢弃 / TimeChat-Online 类机制 | 重复帧 Token 很多且事件保留可评估时 | 慢动作、小物体和静态重要目标对照 | 小变化不等于不重要；需明确更新/重置策略 |
| 事件级记忆森林 | 需要跨窗口回忆，简单窗口/递归状态不足时 | 窗口外事件回忆、固定总预算、事件边界与压缩损失 | 新增外部视觉记忆与树合并；不是修改 KV 就得到森林 |
| SFT | 接口/因果机制正确但目标能力不足时 | 原模型与改造模型的配对错误诊断 | 时间前缀数据、明确冻结/梯度；训练预算另行给出 |

KV Cache 笔记强调保存每层 K/V、减少重复前缀计算但不消除长历史读取成本。适配到 Qwen 时，缓存量公式中的层数只能计实际 full_attention 层，并另加递归/卷积状态；不能用全部 24 层套普通 Transformer 公式。

StreamForest 笔记的可借鉴点是“近期保留细节、远期按事件组织、用内容/时间/历史合并次数控制长期合并”；这属于视觉记忆层设计。若引入到 Qwen，需单独定义记忆特征怎样进入新问题前向、已有递归状态是否保留及是否重建，避免同一历史被重复计入。正式实施前再查原论文和固定源码。

Token 压缩笔记提醒：在完整视觉编码后缩短序列，只减少后续 LLM 开销，不能宣称视觉编码已加速。普通注意力早层 importance 剪枝也不能直接套到以 DeltaNet 为主的混合层。先拆分耗时，再选最简单能解决该瓶颈的操作。

旧 STC 报告记载压缩能加速但存在个别样例退化，本任务沿用配对变化和实际帧数报告习惯，不搬用旧准确率或加速比。

## 学习顺序

基线时学习：processor→视觉 grid→视觉 Token→多模态序列→混合语言层→答案。
增量时学习：历史在哪些张量里、新 chunk 怎么续接、时间/位置怎样延续、ask/reset 的所有权。
优化时学习：先定位瓶颈，再用固定样例比较收益与信息损失；每次只引入一个机制。
