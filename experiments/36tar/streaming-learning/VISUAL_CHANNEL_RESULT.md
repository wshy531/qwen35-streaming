# 视觉通道保留、辅助描述与问答上下文边界

本段完成一个具体的读取适配器：在独立问答上下文中保留原始视觉特征，并可插入中性描述。**视觉通道能补回描述遗漏的狗，但“视觉＋描述”没有比相同任务的纯视觉多纠正一题。** 猫仍答错，而且会受到错误描述中“鸟”的影响。因此保留为诊断，不升级默认。

## 1．先回答你的问题：问答缓存释放后，用户问题去哪了？

准确地说：**问题进入了这一次的问答上下文，但没有自动保留到下一次。** 当前原型把三件事分开：

| 内容 | 当前怎样管理 | 下一次会自动使用吗 |
| --- | --- | --- |
| 视频观察状态 | 新画面继续更新主混合状态；预算满时重置 | 仍在主状态保留范围内的内容可用于后续问答 |
| 某次问题与答案的计算缓存 | 主问答复制分支；历史取证另建独立上下文 | 不自动沿用，问答结束释放或重置 |
| 保存到界面或文件的问答文字 | 可以作为记录保留 | 记录本身不会自动送回模型 |

例如，第一次问“开头是什么动物”，当前分支能看到问题和视频证据并作答；结束后主视频状态继续看新画面。下一次只问“它后来去哪了”，当前实现不能保证知道“它”指上一问的动物，因为没有把上一轮对话作为聊天历史加入。若问题完整写明“0.5秒那只动物后来去哪了”，也还需要对应的取证与时间关系能力；不是换个说法就自动具备。

设计的作用是避免模型自己生成的一句错误答案污染持续观察。例如它误答“这是狗”，这句话不会因此变成主视频历史中的视觉事实。但代价是当前没有完整的跨轮聊天。以后可以加一个**独立、有限的对话记录层**，在问答时显式加入前几轮文本，仍不写进视频主状态；这与长时视频记忆是不同模块，本轮没有实现。

源码核对：`OnlinePairSession.ask`在`main.fork()`上追加问题并生成；`HybridSequence.fork`复制KV、卷积和递归缓存；历史`native_answer`新建会话并在`finally`重置缓存。默认返回结果不含分支缓存；调试`return_evidence=True`可由调用方明确保留它，但不会自动成为下一轮聊天。显存池可能仍保留可复用空间，不代表模型保留了这些对话。这里说的是视频原型，不是你我当前这段聊天。

## 2．为什么继续保留视觉通道

上一轮保存的狗特征直接能回答dog，但自由描述只提花园、树和房子，文字回答器便误答none。把视觉特征变成短文字是一次有损转换；因此本轮检验：让后续回答器仍能看到原始视觉证据，同时把描述当作辅助，会不会更稳。

我们沿用同4个来源帧对、6正常问题及2个早期交换对照，属于针对已见失败的开发诊断，不声称新留出。正常三序列共用同一狗结尾，源帧ID/真实PTS与合成时间分开保存。没有新下载、训练、压缩或森林修改。

## 3．具体改了什么

新增独立`experiments/visual_channel_v1`适配器。先由严格时间索引选中完整48Token帧对；成功后，在一个新建的语言上下文中组织：

```text
固定前缀 → 原始视觉特征 → 可选辅助描述 → 问题与回答任务 → 生成答案
                         （只在这次问答存在）
```

`combined_context`以冻结的`native_context`为基础，只在问题后缀前插入辅助文本。原视觉前缀的嵌入、Token IDs和四轴位置逐值不变；新增文本使用连续文本位置，原问题后缀按新增长度平移。它不是重新视觉编码，也不是把描述写入观察主状态。

```python
base = native_context(model, builder, nodes, task, 24)
cut = input_length - question_suffix_length
new_ids = prefix_ids + auxiliary_ids + question_suffix_ids
# prefix/visual embeddings and positions stay identical.
# question text positions shift by len(auxiliary_ids).
```

辅助描述有128Token、512字符上限，整体输入＋24输出不超过768。问题本身仍受64Token限制；不修改旧核心限制。空、超长、含模板控制符或超辅助Token限额时，明确记录状态，退回同任务纯视觉；不会为了没有描述就丢掉有效画面。正式取证失败仍拒绝，不使用这一回退猜缺失历史。实际GPU八个条件都正常加入描述，未触发回退；回退的等价性由CPU合同验证。

为了避免把问句变化误当架构收益，比较四条路径：原时间问句直接视觉；沿用局部纯描述的文字R；固定短任务纯视觉；相同短任务视觉＋描述。后两条任务完全相同：

```text
Use the video as evidence. Name the animal visible.
Answer dog, cat, bird, none, or uncertain.
```

描述块固定标为可有遗漏或错误的辅助说明，不按结果改词。每个条件中性V只生成一次，文字路径和联合路径共用它。主要配对是后两条，区别只在插入的辅助块及必要的位置平移。相对原直接路径则还改变了任务措辞整体，需分开解释，不能单独归因标签顺序。

## 4．真实GPU结果

| 路径 | 正常6题正确数 | 按不同来源帧对去重 |
| --- | --- | --- |
| 原问句直接视觉 | 5/6 | 3/4 |
| 只读描述 | 2/6 | 2/4 |
| 同任务纯视觉 | 4/6 | 2/4 |
| 同任务视觉＋描述 | 4/6 | 2/4 |

三个正常结尾题复用同一帧对，不是六个独立视频样本。4帧对去重仅为描述统计，不是总体准确率。更直观地看：

| 不同证据 | 真值 | 原问句视觉 | 只读描述 | 同任务纯视觉 | 视觉＋描述 |
| --- | --- | --- | --- | --- | --- |
| 新狗早期 | dog | A dog. | none | dog | dog |
| 共同狗结尾 | dog | A dog. | none | dog | dog |
| 新猫早期 | cat | A cat. | cat | dog | bird |
| 洗手，无动物 | none | A dog | none | dog | dog |

**狗被找回了，但收益不能归给辅助描述。** 只读描述时狗都答none；视觉＋描述改回dog，正常题共有4个纠正，但其中3题是共同狗结尾。相同任务的纯视觉也全答dog，因此没有证据说明描述在这些纠正中提供了额外帮助。

**猫揭示了两种问题。** 原时间问句直接视觉答cat；新固定视觉任务却答dog，说明任务措辞整体就能改变读取。再加入包含虚构鸟的描述后，答bird。后两条均错误；加入辅助块改变了错误内容，没有纠正成cat，不能把“答案变了”当成能力改善。

**洗手仍会误报。** 文字R根据正确的洗手描述答none；两条新视觉任务都答dog，辅助描述没有把它纠正回来。不能因此事后选择“动物题用视觉、无动物题用文字”，那需要先知道真值，而当前没有验证过自动裁决规则。

主配对（加描述相对同任务纯视觉）正常纠正0、损失0、两者正确4、两者错误2。两者同为4/6不是淘汰整个方向的理由，也不是成功；同任务纯视觉甚至6题全答dog，分数受样例构成影响。视觉＋描述相对只读文字纠正4、损失2，不能只展示纠正而隐去猫/洗手的损失。

## 5．早期证据、问答隔离与位置验证

原问句直接视觉继续通过新狗/新猫早期两题以及双向交换；其他三条未通过“两个都正确”的严格终点。交换后，各路径的视觉值/位置、IDs、首logits与生成精确复现另一来源对应条件；错误也完整复现，不包装成可靠利用记忆。

独立审计逐题重建辅助插入：联合IDs等于原视觉上下文前缀＋辅助IDs＋原问题后缀，视觉前缀四轴不变，问题三轴正好平移辅助长度，语言轴连续；投影值相同，问答没有新视觉前向。主状态、源银行、索引和节点不变。

CPU还做了“同一联合问题→插入一次别的文字问答→再次同一联合问题”，结果完全相同；无描述回退与冻结原视觉问答的IDs、位置、首logits、生成完全相同。这些是固定条件下的状态隔离证据，不是新增跨轮聊天。联合会话在`finally`清缓存，权重共享。

与GPU113的8直接、8中性描述、8局部文字R共24锚点，输入IDs、首logits、生成及适用视觉位置全部相同。13正式缺证据/不支持请求零前向，包含3次移除早期；拒绝不算语义none或模型准确率。

## 7．本段结论与后续边界

完成的架构学习成果是一个可解释的独立读取接口：保留视觉证据、显式加入辅助文字、正确衔接位置、回答后清问答状态，同时保护视频观察与外部历史。它验证了两种不同风险：只留文字会遗漏；视觉和文字简单放在一起也不保证正确融合。

当前原问句直接历史读取继续作为参考，文字与联合路径保留为诊断，不升级默认。不继续按这几个失败反复搜提示，也不新增事后挑答案的路由。若后续研究联合读取，应先固定独立反例，分别核验视觉本来可读、描述遗漏/错误/正确时的行为，再决定是否需要学习更可靠的证据融合。

持续用户追问若成为需求，应单独设计有上限、可清除的聊天记录层，明确用户陈述与模型猜测的区别；不能把本次联合读取当成已经实现聊天记忆。旧综合汇报未修改，后续实际进度只看实验总纲。
