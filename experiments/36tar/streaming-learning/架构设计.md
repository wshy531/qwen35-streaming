## 3. 原路径与改造路径

离线参考：已采样的全部帧→逐帧视觉特征→投影/池化→拼入完整视频提示→语言模型 prefill→生成。

外部每秒重新调用该完整流程，会重复编码和 prefill 历史；这不是本任务要交付的机制。

我们的方案：

```text
reset → 编码固定提示前缀 P → 主状态 S0
新帧 x1 → 视觉编码/投影 z1 → LLM(z1, S0) → S1
新帧 x2 → 视觉编码/投影 z2 → LLM(z2, S1) → S2
                                            │
ask(q) → 复制 S2 → 视频结束符 + q + 助手前缀 → 生成答案 → 丢弃分支
新帧 x3 → 视觉编码/投影 z3 → LLM(z3, S2) → S3
```

这里修改的是模型执行结构、状态管理与接口，第一版不新增可训练权重。缓存是模型内各层真实 KV，不能用外部文字摘要或原始帧列表冒充。

主序列始终是“固定前缀 + 已到达的视频帧 embedding”，问题不写入主状态。这样可以换问题、连续提问，而不会让旧答案影响后来帧。V0 不保留对话历史，用户问题必须自包含。

## 4. 模型接口契约

```python
reset(session_id) -> StreamStatus
append(frames, timestamps) -> StreamStatus
ask(question, max_new_tokens=64) -> AnswerRecord
close() -> None
```

- 单视频、batch=1；默认一次 1 帧；接口允许连续多帧，但只能在该 chunk 全部到达后回答。时间戳单位秒，严格递增；不使用完整视频总长度决定采样位置。
- `append` 验证帧数、时间戳、token 容量后才计算/提交状态。参数/容量拒绝必须不改状态；底层计算异常若不能回滚则标记状态失效，要求 reset，不能继续使用半更新缓存。
- `ask` 使用当前状态副本，禁止浅拷贝可变 Cache；一份分支完成即释放，不并发保留多份。问答前后核对主缓存长度与内容摘要。
- `reset` 清除 KV、帧计数、时间戳、位置、有效标志；保留模型权重；新会话重建相同固定提示前缀。测试时比較 reset 后的状态与全新实例，而不是要求前缀 KV 长度为零。
- `close` 释放会话资源并拒绝 append/ask，直到再次 reset。
- 返回值记录 session_id、已接收帧数、当前时间、缓存长度、状态字节数；答案记录对应状态版本，便于查明回答看到了哪些帧。

## 5. 张量、位置、mask 与模板

设新 chunk 有 F 帧，视觉输入 `[1,F,3,H,W]`；经原模型视频视觉路径得到 `[1,F*P,D]`，P 为实际每帧 token 数，D 取文本 hidden_size。P、H、W 均从处理器/实际张量确认，禁止只相信旧记录的 196。

各层 KV 逻辑形状 `[1,H_kv,L,D_head]`。追加 m 个 token 后 L→L+m；不重新输入旧帧的 embedding。新位置为 L…L+m−1，padding 初版关闭。2D attention mask 覆盖完整 L+m 的有效位置；实际 causal mask 必须确保新位置 i 只能看历史和本 chunk 中 ≤i 的位置。

原视觉编码器可以看同一帧的所有 patch；这不泄漏未来帧。只要尚未到达的帧从未进入视觉编码和采样，帧内非因果注意力不影响跨帧因果约束。仍需检查预处理有无全视频归一化或未来依赖。

模板构造须从真实 processor 输出拆出 P / 视频占位区 / Q。固定 user 前缀一次编码，新增帧填充视频占位区，视频末尾的 newline 与问题、user 结束符和 assistant 前缀只进问答分支。不得每个 append 都加视频结束符，也不得反复 tokenization 完整历史后假定新 token 是旧序列的后缀。先直接比较完整 processor 的 token/embedding 拼接结果。

时间戳先仅存元数据、用于帧顺序和证据，不新增时间 token 破坏离线格式。首版验证颜色变化/事件先后，不承诺精确秒数回答。

## 6. 官方源码定位与实现边界

本次核对的是 Transformers **v4.57.1**，不是远程实际安装版本。以以下函数名定位，安装后重新核对：

| 文件 / 入口 | 要理解的操作 | 我们的改动位置 |
|---|---|---|
| processing_llava_onevision.py / processor | 视频占位 token 展开 | 核对前缀/视频/问题边界 |
| modeling_llava_onevision.py / get_video_features | 视觉特征、投影、池化 | append 仅输入新帧 |
| 同文件 / forward | 视觉 embedding 替换与语言模型调用 | 适配层传 inputs_embeds、缓存与位置 |
| 同文件 / prepare_inputs_for_generation | 生成时输入裁剪和视觉输入处理 | 不能直接拿多次 generate 当视频追加 |

该版本视频路径在帧特征后加一个 newline；生成准备路径按 cache_position 决定是否传视觉输入。两点都要求单独实现视频更新入口，并做一次性与分块的一致性检查。

## 7. 历史寿命与内存预算

V0 默认 max_frames=16、max_stream_tokens=4096；超过任一限制时 append 拒绝并保留现状态，仍可 ask，用户明确 reset 后开启新会话。每次输入前还需检查模型真实最大上下文，确保问答预留可用。

以历史常见 P=196 举例，16 帧为 3136 个视觉 token，加固定前缀；这只是估算。主 KV 字节约 `2*N_layers*H_kv*L*D_head*bytes_per_element`。提问时另有一份缓存副本及问题/输出 KV，峰值必须计入二者、模型权重、视觉激活与运行时开销。0.9B 权重以 2 字节估算约 1.8GB，不是总显存需求。

首次 smoke 建议单卡 A800、batch=1、1–4 帧、最多 16 输出 token、10 分钟作业上限；通过后最多 16 帧/64 输出 token、20 分钟机制验证上限。均为后续预算建议，本轮不提交。先测峰值、耗时再报实际成本，不承诺实时速度；GPU 排队不计入模型延迟。

持续无限输入是 V1 扩展任务：必须选择淘汰/摘要策略并验证质量损失、RoPE 和状态上限。不可把手动重置短会话说成具备无限历史记忆。

## 8. 最小验收矩阵

| 检查 | 对照与证据 | 判定 |
|---|---|---|
| 增量等价 | 完全相同帧和模板，一次 prefill vs 1/2/4 帧分块；比较同一问题首 token logits，必要时逐层输出 | 先 FP32 小配置参考，再低精度真实模型；预先记录容差，不能只看答案相同 |
| 不读未来 | 相同前缀接两种不同后缀；t 时刻状态/logits相同；记录解码器实际已读取的帧 | 模型输入不含 >t 帧；不用未来总长度采样 |
| 增量计算 | vision hook 记录 frame_id；LLM hook 记录新增 query 长度 | 历史帧不重复编码、append 不重复 prefill 旧 token |
| reset | A→reset→B 与新实例→B | 状态/输出匹配；无 A 历史残留 |
| 问答隔离 | ask(q1)、ask(q2)、继续 append 与从未 ask 的运行对比 | 主状态不变、后续视频状态匹配；空缓存或零拷贝假实现不能通过 |
| 容量与异常 | 容量边缘 append、重复时间戳、非法 shape、close 后操作 | 明确拒绝；预检错误不改旧状态 |
| 视觉证据 | 相同末帧，改变早期关键颜色/物体，问“先前出现什么”；另做遮掉关键帧对照 | 配对答案/正确率随正确证据变化；仅 logits 变化不足以证明理解 |
| 时间证据 | A→B 与 B→A，使用同一问题问顺序 | 对比最后一帧基线，排除只看当前帧的解法 |
| 有界资源 | 连续运行至上限、重复 ask/reset；记录 tensor 字节与 allocated/reserved | 活跃状态受限；区分显存缓存保留与真实泄漏 |

数据：先生成少量无版权争议的色块/几何物体视频，每条 4–16 帧，覆盖前后顺序、历史与末帧冲突；按序列划分调试与留出，不能把同一序列不同前缀分到两边。再用 3–5 条明确来源/授权的自然视频做演示。合成机制测试与自然视频能力分别报告，不包装为基准成绩。

## 9. 何时训练

先全部冻结、eval + inference_mode，V0 没有反向传播。若缓存等价不过，修接口；若单帧识别不过，先诊断视觉输入；若离线能答而增量不能答，先查模板和位置，不立刻训练。

只有结构正确而目标任务确需适配，才考虑少量前缀问答 SFT，起步冻结视觉和投影，仅对语言模型少量层做 LoRA；这是一项待论证选择。训练序列只含截至 t 的视频和问题，labels 对前缀/视觉/问题设 -100，只监督答案。正确答案不得依赖尚未到达的后缀。

训练可用完整“可见前缀”的因果 teacher forcing，并不必强行在有梯度的 KV 缓存上循环。若之后新增可训练记忆模块，则另行明确梯度跨 chunk 的保留/截断，并检查非零梯度、权重更新、保存重载一致。不会预设 GRPO。
