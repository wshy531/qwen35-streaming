# 关系表述和缺证据：答案会跟着什么变化

2026-10-15固定结果；唯一持续进度为《实验总纲.md》，旧综合汇报不改。

**这轮确认：输出格式已经合格，事实判断仍会受题面和选项顺序影响；缺证据时也仍会猜答案。** 不能靠选择一个看起来分数更高的顺序，把它包装成读取架构已经修好。

## 为什么做这轮

上轮发现背景有人却答no，缺毛色/缺顺序却不答uncertain。直接再加一句拒答提示，无法说明错误为什么发生。本轮沿用同一个结构化提示，不找新提示，只做固定的成对文字控制。

16个主案例各跑正常/反向选项，共32次；另外3次完整复现GPU109的原条件，总共35次调用。全是人工文字控制或原文字条件，没有看图、视频解码或新视觉收益。它是已知问题的开发诊断，样本相关，不能当通用准确率。

## 如何避免混淆

主案例的问题统一去掉原来的 `Answer ...` 及内嵌选项，选项仅在提示中出现一次，再反转这个列表。两种顺序都完整保留，不能事后挑一种。

同时保留三个原条件锚点：原背景人物题、缺毛色题、缺顺序题，题面和选项完全不动。这样可以检查是不是我们把旧失败条件悄悄改掉了。三锚点的输入IDs、首logits、生成IDs都与GPU109完全同一，原错误都复现。

每次回答独立新缓存，最多24Token，无强制标签解码。主评分为规范标签精确匹配，旧别名另报；本轮所有35答均为合法标签且EOS结束，所以这里的失败不来自长句、截断或格式。

## 关系对照的全部8个主案例

| 描述与提问 | 事前答案 | 正常选项 | 反向选项 |
|---|---|---|---|
| 狗在前景、女人在背景；问狗后有人吗 | yes | yes | no |
| 同上；问背景有女人吗 | yes | yes | yes |
| 女人在狗后；问狗后有人吗 | yes | yes | yes |
| 女人在狗后；问背景有女人吗 | yes | yes | yes |
| 明确背景无人；问狗后有人吗 | no | no | no |
| 明确狗后无人；问狗后有人吗 | no | no | no |
| 女人在狗前；问女人在狗后吗 | no | no | no |
| 狗在女人后；问女人在狗后吗 | no | yes | yes |

四格里的前景/背景按本诊断场景约定对应前后关系，不是任意空间描述都可以这样互换。正常顺序关系7/8，反向6/8。

最后两题表达同一基本位置关系，只是换了主客语法。第一题能答对，第二题答反，说明这个小模型的关系读取不够稳。两条明确否定都能答对，因此也不能笼统说它完全不会理解否定。

第一题尤其值得保留：原完整问题 `Are people visible behind the dog? Answer yes or no.` 的锚点仍答no；主案例去掉尾部Answer指令后，正常选项答yes，反向又答no。这说明题面与选项顺序会影响局部行为，**不是仅凭background一个词就能解释全部错误**。输入文字、Token和位置一起变化，不能归因某一网络层。

## 毛色与顺序的全部8个主案例

| 描述 | 应答 | 正常选项 | 反向选项 |
|---|---|---|---|
| 明确猫是黑白色 | black-white | black-white | black-white |
| 只说有一只猫，没有毛色 | uncertain | black-white | white |
| 明确说毛色没有说明 | uncertain | black-white | white |
| 只说猫在地上走，无毛色 | uncertain | black-white | white |
| 明确先猫后狗 | cat | cat | cat |
| 明确先狗后猫 | dog | dog | dog |
| 只说有狗和猫，没有顺序 | uncertain | dog | dog |
| 明确说顺序没有说明 | uncertain | dog | dog |

有明确信息的毛色和顺序控制都答对。缺信息的5题，两种顺序全部没有正确拒答，仍是0/5。

毛色三题在同一描述/同一问题下，仅改选项顺序就从black-white改成white，**答案没有新增证据却变了**。反向后uncertain排在最前，它仍不选uncertain；因此现象也不是“永远选第一个”这么简单，更不是把拒答选项挪前就能修好。

模型说出一个合法颜色，不代表描述里真的有颜色依据。不能把选项顺序敏感当作提高识别能力的方法。

## 实现与验证

独立实验 `experiments/reader_controls_v1`，冻结一个既有结构化模板及19条记录。正常/反向共35问答；只改指定选项列表，成对次序交替。GPU前固定真值和评分，不按答案改题或挑顺序。

CPU四合同及完整35随机模型重放通过：输入边界；新缓存重复、rope恢复及无视觉；16组提示除选项字段外相同；三锚点IDs与原运行一致。随机答案不作能力证据。

GPU110实际一次载入，0视觉、111语言前向、35问答、76生成Token，全EOS。峰allocated3.2273GiB、reserved3.3828GiB。载入加replay记录9.50秒，不含全部启动开销，不是实时视频或公平速度指标。

预算1load/0vision/35QA/840生成/920语言/360秒，纯文字384上下文，FP32 IEEE/math greedy，RAM3GiB/GPU空闲5.5GiB/转换余量2GiB门禁保持。独立审核核168源、模型资产、来源条件/锚点、全部35原答、16仅选项顺序配对、状态恢复、资源与预算。无训练、无视觉/森林/默认核心修改。

完整逐题描述、问题、原答和配对结果均保留在audit的answer_review与paired_results，三锚点复现也逐项记录。

## 下一步建议

本轮文字排查先到这里，不继续批量改提示。现在已知道：**部分关系映射不稳、缺证据仍猜、合法格式不能代替事实依据。** 两阶段候选继续保留，尚未达到默认接入条件；这些结果也不能反推森林存储必然有错。

下一段更贴近流式架构学习的工作，是利用已有时间索引做有界对照：同一历史问题，比较“全部时段一起描述”和“先定位目标原始帧对，再独立描述/回答”。明确保留来源时间与证据状态，检查是否减少混入近期主体、丢失首段的现象。

程序可以可靠拒绝已淘汰、未到达或根本没有保存的帧对；**保存了帧对，不代表模型描述已包含答案**，所以这层结构检查不能包装成语义缺失问题已经解决。还要保留原始特征读取参照、逐题纠错与新增错误，之后再考虑训练或更深改造。
