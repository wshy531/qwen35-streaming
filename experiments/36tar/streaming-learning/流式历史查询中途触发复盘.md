# 流式历史查询中途触发复盘

日期：2026-10-12。持续进度只读《实验总纲.md》。本段改变查询发生的时机，模型权重、FP32/64混合状态核心、帧库政策、默认关闭均不改。

## 新增了什么

上一段通用CLI在文件结束后查询预设历史目标。新增`--history-query-after 3`，模型实际编码到3秒后，在同一消费者中执行这些请求一次，然后继续视频输入。
必须依据已完成编码的位置；刚收到、仍等配对的一帧不触发。阈值没达到就结束，summary明确pending，不在EOF静默补问。奇帧EOF补编码后达到阈值的情况标记输入已结束。
不传此选项，仍按文件结束后的旧默认时机查询。页面同时显示请求哪个历史时间、执行时已编码到哪里、是否已结束，避免把“提问时尚未观察”误读成“以后一直无法回答”。请求不会自动重试，也不是实时交互聊天。

## 实际事件顺序

同一受控犬→鸽→猫六帧，无损媒体与来源映射沿用上一段；会话0..5秒明确为合成时间，不是自然事件先后。

| 发生时机 | 系统操作 | 实际结果 |
|---|---|---|
| 已编码0–1秒 | 当前动物问答 | 犬回答dog |
| 已编码2–3秒，主状态已reset | 当前动物问答 | 鸽误答dog，保留 |
| 仍在第3秒 | 查询0.5秒 | 从独立帧库取回犬，回答dog；主状态不变 |
| 仍在第3秒 | 查询2.5秒 | 正确取回鸽，但误答dog；主状态不变 |
| 仍在第3秒 | 查询1.5秒 | 帧对之间无保留证据，0模型调用 |
| 仍在第3秒 | 查询4.5秒 | 猫画面尚未接入，拒答，0模型调用 |
| 后续编码4–5秒 | 继续输入、第二次reset、当前问答 | 回答cat |

这次可直接观察架构的因果边界：系统可以查询已经保存的旧画面，但不会因为完整视频文件里存在后面的猫，就提前把它当作已观察证据。查询之后还能继续处理新画面。答案内容没有学习新知识；鸽误犬在上一段未改模型相同输入中也复现。

## 本段验证

47项通用CPU预检、完整171项CPU回归和额外程序中途查询续接契约通过，源码测试前后不变。四个新增契约覆盖中途触发、待配对单帧、未达阈值及奇帧EOF。CPU为微型随机模型与软件测试，不证明语义。
GPU72在载入前因RAM2,852,421,632B低于3GiB门槛拒绝，0模型载入；失败证据保留，没有降低门槛。用户释放内存后实际测得可用6,934,495,232B，再按同proof/同预算/新run提交GPU73完成。
真实第3秒历史事件位于EOF和猫帧编码之前，两次生成主KV/卷积/递归逐位不变。3当前和2历史生成与上一受控输入的对应生成IDs同一；只有3独立画面输入，不当5个独立能力样例。
实际5视觉/45语言/35词表输出行，allocated峰值3.28249GiB，含载入6.089秒。没有端到端提速比较；本次fast因果回放，不冒称按墙钟播放、摄像头或长期自然视频已验证。

## 怎样运行

仍从个人目录用`python scripts/run_video_demo.py`，先fresh CPU，再同参数GPU。沿用上一复盘的六帧参数，将历史目标改为0.5/2.5/1.5/4.5，并增加`--history-query-after 3`；历史问题与当前问题都是`Name the main visible animal.`。
例如新增参数：

```powershell
--remember-history --memory-every-pairs 1 --history-query-after 3 `
--history-time 0.5 --history-time 2.5 --history-time 1.5 --history-time 4.5
```

这一段是需要附加到完整命令中的参数，不是单独可执行程序。fresh out/CPU证明与原RAM/显存门禁继续要求。视频、问题、源或参数变化须重新预检。
