# Optional file entry for bounded strict-time feature retrieval

Use unchanged main EventRuntime and RawTimeIndex/native reader in an independent optional entry, not a default-core modification. Accept video path,1FPS by default, sampling rate, duration, frame limit,1..3 retained pairs, reset schedule, EOF questions and a bounded query-plan file. Time is the real file PTS normalized by the frozen sampler, not synthetic case time. No camera. Question grammar remains the two English templates. Decode and encode new pairs once; index commits only after successful main feed. Show union of retained intervals, global encoded horizon, main-memory epoch, dropped odd EOF sample, selected pair and source frame IDs. Unsupported/missing/evicted/gap/future requests return structured no-evidence without invoking the model. This does not judge whether a retained frame contains the requested object.

Keep at most3 raw48-token pairs, plus optional small JPEG display previews for those pairs and one pending canvas. Previews are for display only; queries reuse saved projected features and do not re-encode JPEGs. Terminal events and an offline HTML report show evidence/answer/refusal. HTML escapes source/question/answer text, and previews remain local media excluded from Git/backup. Do not precompute a full video pool. Query-plan triggers not reached are reported pending, not silently moved to EOF.

Acceptance configuration: old cat video,1FPS,max9 real samples,duration12 seconds,index3,main256; explicit main resets after pairs1 and3.13 predeclared attempts:6 expected model calls,7 refusals spanning empty/future/eviction/pair gap/odd EOF/unsupported. Check repeated old query before/after main reset identical, then continue input and evict old pair. Questions within the same pair interval refer to the sampled pair, not an exact intermediate frame. This is mechanism acceptance; cat/dog errors remain separately reviewed and are not evidence of interface failure.

GPU budget is derived from CLI:≤floor(max_frames/2) vision calls;≤number of planned+EOF attempts model calls;24 tokens/call,language≤2*pairs+25*attempts+16;360sec watchdog. Frame limit2..32,fps0.1..4,duration≤60sec,file≤64MiB; at least one question/plan. Main256..512/QA768, features conservative≤8MiB,RGB+preview temporary estimate≤2MiB. RAM≥3/GPUfree≥5.5/conversion≥2GiB unchanged. CPU failure/EOF/ownership/eviction/query isolation/continuous input contracts and fresh actual-file replay before GPU. Input/model/source/query-plan SHA and exact request must match. No training,compression,default edits,comprehensive-report additions or arbitrary semantic retrieval claim.

Final file adapter permits only1e-9sec absolute roundoff tolerance at retained-pair boundaries, preserving original PTS in evidence. A decoded0.9999999999999999 endpoint may cover request1.0; request1.00001 or a true inter-pair gap remains refused. This is not nearest-frame retrieval. Initial GPU97 acceptance completed before this boundary issue was noticed in source inspection; keep it and CPU01 failure/02/03 successes. Final CPU04 and GPU98 repeat the same configuration, adding the boundary regression contract without relaxing resource gates or changing the13-query expected acceptance outcomes.
