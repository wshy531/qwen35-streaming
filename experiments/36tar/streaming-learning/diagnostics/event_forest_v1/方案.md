# StreamForest启发的CPU事件Token调度原型

固定官方参考提交f9d14670ff451ff5865638e17c9958e99bf2fec5，参考manager与Apache许可保持原样，来源和SHA见reference/SOURCE.json。本代码自行实现调度与安全边界，不导入训练环境或加载预训练模型。
输入是人为给定的合成事件特征，事件切分、真实视觉特征和Qwen位置协议尚未适配。最近视觉窗口也不在本原型内；这里只研究长期合并。
三项分数取官方helper的相似度、从1开始累加的计数、平均事件时间/当前时间，最低分相邻事件合并。ToMe式一次匹配与固定参考3组非零随机输入比较。合成事件16Token×16维/4头，长期64Token；奇数Token数用ceil输出。跨层保留原始Token质量权重、真实事件数加权时间是本原型的显式差异，不声称全数值复现。
每写入一次就检查Token/元数据限额；只保压缩根表示、区间/计数，不保所有子Tensor或内部无界历史日志。区间只代表压缩来源范围，不保证任意时刻都有精确画面，不能混用原帧库retained_interval语义。
预算：0GPU/0真实权重/0训练/无新媒体；8CPU契约、3同级ToMe控制、4权重设置×24合成事件、512事件压力与固定官方update/get helper探针。另加同64Token/4352B的FIFO最近4事件、首锚点+最近3事件输入对照，两臂同样计入单位质量张量；这是合成特征预算，不与旧864KiB RGB帧库混算。长期特征及质量张量≤4352B，根Token≤64，元数据JSON≤16KiB（不是Python实际堆内存）；临时匹配矩阵/拼接/导出另算，最大匹配维度受64+16输入上界控制。只给短场景写trace，压力只保汇总；墙钟独立记录。
测试包括预算、零向量、非法输入不变、输入/输出所有权、旧子张量释放、质量/均值守恒、时间选择及一个明确的相反特征抵消反例，不能用来源区间覆盖当信息无损。
默认活动实现不变；通过后仍只称CPU调度原型，不称真实森林复现、真实视频准确率或Qwen流式新能力。下一视觉Token/事件边界/位置编码适配需新方案与GPU预算预检。持续进度仅实验总纲。
