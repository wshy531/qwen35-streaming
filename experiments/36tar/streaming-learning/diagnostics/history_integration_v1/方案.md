# 有限历史证据接入通用视频入口

本段不是性能优化。假设：容量重置后主状态忘记早期输入，独立有界帧库可以向历史问答分支提供仍保留的旧画面，且不改变主状态。
新模块是显式可选功能，默认关闭；不训练、不改权重/FP32/64，不改冻结实验。

## 输入与控制
使用已有署名dog/pigeon/cat素材各2个1FPS采样帧：dog从采样序号12开始（跳过片头），pigeon/cat从0开始，等比补边为192×256，FFV1无损组成6帧MKV。
会话时间0..5秒为明确合成时间；来源实际PTS、帧ID、文件/画面SHA保留，不把拼接当自然事件。
重新解码逐帧核验画面与PTS完全相同；素材只存本机，不进Git/交接备份。

当前问：Name the main visible animal.；2帧首问，每2帧一次，答案最多16Token。
历史问同上，查询0.5/2.5秒（已保存），1.5秒（帧对间无证据），99秒（未来）。
总Token200，问题保留96，回答保留16，主预算88；预期每新对触发容量重置，实际日程由CPU proof确定。
帧库每1对保存，最多3对/864KiB持久RGB。存入可暂时多持有1对，查询返回另1对副本；不把持久像素限额当作总进程RAM。

## 预算和预检
先完整CPU接口与实际视频预检，绑定所有活动源码/启动器/问题参数/视频SHA/模型资产，再真实GPU。
最多1次真实权重载入、6真实帧、7问答、10视觉forward、148语言forward、112生成Token、200Token会话、600秒含载入硬看门狗；实际限额以通用budget.json公式为准，更紧者优先。
RAM≥3GiB/空闲显存≥5.5GiB/FP32转换空间≥2GiB；单模型，不降门槛。
验证：当前每epoch只含新帧；旧证据0/1与2/3可取回；1.5/99秒不调用模型；每个实际历史回答主四类状态不变；清理后帧库为空；默认关闭路径回归。
答案识别对错另报，不能把取回正确画面当理解正确，不假设鸟样例已修复。

命令仍用scripts/run_video_demo.py，显式追加--remember-history --memory-every-pairs 1与四个--history-time。
原模型同输入复核独立使用run_original_check.py的240秒含载入看门狗：3个真实独立帧对、3视觉/51语言/48生成/200Token、单模型及相同资源门槛；fresh CPU绑定其源码/启动器和实际流式记录。输出与3当前+2历史路径分别比较，仅3个独立输入，不计作5独立能力样例。
真实结果与持续计划仅以本机《实验总纲.md》为准。
