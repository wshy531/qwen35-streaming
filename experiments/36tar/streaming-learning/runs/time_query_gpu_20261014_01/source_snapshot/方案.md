# Time-directed old-evidence readout and interference

No compression. Two dog/cat orders with identical washing suffix, repeated with separately fixed source windows. Each is three raw pairs/144 stored visual tokens. Session0..5 is synthetic; original source frame/time/SHA kept. Query at0.5 or2.5 seconds asks animal, plus early coat. Same question across single target48, target+recent96, all144, automatic restricted-time route48, target-value-only swap48 and recent-only48. Four cases×three questions×six conditions=72 QA. All cases/questions chosen before current answers; these are known old sources/windows, not new-source generalization.

The index accepts at most three exact raw pairs, evicts oldest on append, and parses only the two explicit question templates. Selection uses parsed time and stored intervals, never animal/color labels or expected target index. Unsupported/ambiguous/gap/future/evicted/compressed-only requests produce a structured no-evidence result and must not call the model. This is restricted time lookup, not arbitrary language or semantic retrieval. The single-target arm uses an explicitly annotated target solely as oracle diagnosis; routed is independently computed. Swap keeps target prompt/positions/mass/coords but substitutes the other old animal's values; it is marked artificial counterfactual with donor metadata, never written to the real bank.

Each case clears the main mixed state after all three pairs, preserves the external nodes and horizon, and runs independent QA contexts. This confirms external readout does not depend on main cache still holding old video. Oracle vs route must have identical input values/positions/IDs and generation. Mixing changes context length, labels and positions as well as other visual evidence; an effect is context interference, not a pure attention or recent-pixels causal proof.
