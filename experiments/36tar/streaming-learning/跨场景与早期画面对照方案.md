# 跨场景与早期画面：固定配对验收

2026-10-10。进度主记录为实验总纲。本轮在同步成对帧演示后检查主体更新和早期画面利用，不增加训练、压缩、记忆森林或KV裁剪。

## 固定输入和问题

使用现有Commons猫与洗手真实素材，各取1FPS前6个真实PTS采样包。已查看12帧接触表，猫和手主体清楚；输入来源/原frame_id/原PTS/RGB SHA见runs/s4b_scene_fixture_20261010_01/fixture_sources.json。猫源作者Riverarvi，CC BY-SA4.0；手源CDC，公有领域。原文件不改。接触表猫部分及本次派生猫画面沿用CC BY-SA4.0，详尽来源/许可在datasets/natural_commons_v1/manifest.json和ATTRIBUTION.md。

各源RGB统一双三次缩放192×256，再在内存构造6帧实验序列。猫原比例会改变，固定对照不在失败后换画布。实验frame_id=0..5、实验PTS=0..5秒；原frame_id/真实PTS另列元数据。它们是人为拼接的受控画面序列，不是真实连续拍摄/自然事件发生顺序，不宣称流式现场采集。派生像素/真实来源标签不进入问题或模型输入。

固定LAST题沿用原Q1：What is the main visible subject in the LAST frame of this video window? Answer only CAT, HANDS, or OTHER.

固定FIRST题仅把LAST换FIRST：What is the main visible subject in the FIRST frame of this video window? Answer only CAT, HANDS, or OTHER.

每组沿用PairDemo第4/6真实帧自动问LAST（共8次），第6帧另问FIRST（4次）。容量176主Token/256总Token，6帧应171主Token，无reset/EOF补帧。两组相同末对的对照必须具有完全相同末对RGB、完整Token/位置/时间布局；只早期视觉不同。另做hands/cat末对独立2帧控制，各问LAST和FIRST共4次，使用同样实验PTS4/5；其窗口第一帧就是末对首帧，不称它能推断已删除的原始第一帧。

每组第6帧两题都比较独立整段语言参照（8次）：复用实际新增对编码出的视觉特征，独立重建完整Token/四轴位置/文本embedding，断言完整实际embedding相同后prefill+生成。此处故意消除独立视觉编码的数值差异，不是原未改模型或独立整段视觉的能力基线。沿用既有FP32严格门槛max≤.01/mean≤.0001/RMS≤.0003且allclose(atol=rtol=1e-4)，四缓存状态allclose1e-4，生成IDs完整相同；所有在线问答的主四状态/计数逐位不变。

## 预算、预检和判据

先CPU微型权重同流程预检；核验四组、两末对来源SHA、统一画布、末对逐位相同/早期不同、布局全同、问题预留、4/6触发、主隔离、8组同实际输入语言参考、reader/hooks/cache清理。随机答案不算能力。冻结10模型文件、2源视频、来源JSON/接触表、全部源文件、计划、启动器与输入指纹/时间线后，才执行一次本机GPU。

一次GPU固定4×6帧+2×2帧（28实验输入帧），14视觉编码，24问答生成（16在线含4末对控制+8独立语言参照），每次≤8输出Token/总≤192生成，语言forward≤236 = 20主prefix/新块 + 24问题prefill + 192生成；一次权重加载，FP32 IEEE+math、256Token总上限、600秒watchdog。载入前显存空闲≥5.5GiB且RAM≥3GiB，BF16载入后转FP32前≥2GiB显存。固定序列做完即停，不因语义失败改题、换帧或补跑；接口/资源失败留证据。

分别报告：接口数值/隔离；四帧当前主体4例、六帧当前主体4例、六帧第一主体4例、末对控制4例；两变化场景是否正确从前主体切到后主体；两个相同末对的FIRST配对是否都正确且答案随早期画面变化。生成答案相同、logits变化或单组正确不足以称历史利用通过。FIRST成功仅证明本短序列早期主体利用，不等于先后事件推理、长记忆或重置后记忆。现有BF16和不同视觉编码严格失败仍保留。

新增独立scene_pair_control模块/启动器；不修改旧48源码文件与模型默认路径。每次新run，保存输入/事件/实际回答/计数/严格指标/资源/源码快照，只有小型证据入备份，不复制媒体/权重。四组案例内存保留只是有限诊断，不能拿它宣称在线应用无限存帧。
