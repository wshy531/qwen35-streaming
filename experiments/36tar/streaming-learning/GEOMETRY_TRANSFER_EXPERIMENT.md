# 冻结棋盘格规则后的运动片段检查

2026-10-14固定结果快照；持续进度只看《实验总纲.md》。本阶段没有更改综合汇报、默认模型或冻结的选择规则，没有训练。

## 为什么做这轮

上一轮在猫视频开头发现：同为48个视觉Token，互补棋盘格和偶数列能读对深色毛色，原融合与奇数列却答浅色。一个案例成功可能只是刚好保留了该题需要的信息，所以这次先固定棋盘格，不看结果再改规则，换片段检查。

结果是：**它没有显示稳定优势，而且出现了一项新增损失。暂不作为默认压缩方式。** 这个负结果帮助我们及时停止把局部成功推广成架构收益。

## 我们改了什么

新增独立诊断目录`diagnostics/geometry_transfer_v1`，直接调用上一轮冻结的选择与读取实现，没有再写一套新的压缩器。

| 对照 | 视觉Token | 内容 |
|---|---:|---|
| 完整参考 | 96 | 两对画面的全部投影特征 |
| 完整首对 | 48 | 第一对的完整网格 |
| 原融合 | 48 | 原ToMe融合结果 |
| 棋盘格 | 48 | 两对各取24个互补格子，合起来覆盖6×8网格 |

棋盘格仍按`(row + col + source_pair) % 2 == 0`取值、按空间位置排列，使用原来源坐标。没有用问题、答案或人工标注决定取哪些Token。四种方案都用独立问答会话，不把答案写回视频主状态；主状态仍维护KV、卷积、递归状态。

输入共六例，各三题，四方案共72次真实问答：

- 猫第4—7个1FPS采样帧、狗第20—23个：主体、毛色、背景是否有人。
- 洗手和免洗手卫生视频各第8—11个采样帧：动作、使用物、动作先后。
- 狗第20—21个采样帧接猫第4—5个，以及反向拼接：最早动物、最后动物、出现顺序。

两组拼接是明确的人造顺序控制，不是自然视频发生了场景切换。所有会话使用合成的0—3秒标签，原文件真实PTS、帧ID和像素SHA另存，没有冒充真实播放时序。

这些帧没有用于GPU91/92的规则选择，但视频源早已在项目中使用，部分帧也有更早实验记录。因此这里只能说“相对规则选择的迁移检查”，不是全项目从未见过的新数据或正式泛化测评。六张接触图和人工真值均在真实回答前核验、保存。

## 实际效果

| 检查内容 | 完整96 | 首对48 | 原融合48 | 棋盘格48 |
|---|---|---|---|---|
| 较晚猫：主体 | 狗✗ | 狗✗ | 狗✗ | 狗✗ |
| 较晚猫：毛色 | 深色✓ | 深色✓ | 深色✓ | 浅色✗ |
| 较晚猫：背景无人 | ✓ | ✓ | ✓ | ✓ |
| 狗：主体、毛色、背景人物 | 3/3 | 3/3 | 3/3 | 3/3 |
| 洗手：粗动作、肥皂、连续动作描述 | 3/3 | 3/3 | 3/3 | 3/3 |
| 免洗手卫生：动作、物体、先后 | 0/3 | 0/3 | 0/3 | 0/3 |
| 两组狗猫顺序：首、末、完整顺序共六题 | 2/6 | 2/6 | 2/6 | 2/6 |

这18个检查不是18个独立视频，不报告通用准确率。最有用的统计是：完整参考能答对的10项里，首对和融合各保留10项，棋盘格保留9项，新增损失是较晚猫的毛色。三种48Token方案在完整参考失败的题上都没有新增正确项。

为什么这个结果值得重视？上一轮猫开头的毛色由棋盘格保住，这一轮换到猫的后半段，它却丢掉了毛色。**固定几何规则并不知道哪部分特征对当前事实重要。覆盖了全部空间格子，不代表完整保留了信息。** 同时，这里的策略还包含时间采样、排列与应用位置，不能把变化完全归因于空间覆盖。

## 哪些问题并不是压缩新增的

较晚猫在完整96Token下已经被认成狗；这一主体错误不能算压缩造成。逆序拼接中，未压缩参考也未能完整列出狗、猫顺序，回答经常出现“dog、woman”或两次dog。因此，这一组不足以证明棋盘格破坏顺序，也不能证明它保住顺序。

免洗手卫生片段实际是从墙上装置取液，再搓手。模型却描述成拿瓶子往装置里倒液体，或拿纸巾卷放到台面上。这些基础读取错误在完整输入已经出现，压缩未修复。部分长答到24Token上限而中断，原输出和停止原因都保留；不能把截断回答自动视为完整正确的动作链。

有两个评分边界需要公开：

- 洗手片段主要是连续搓洗，没有清晰分开的多事件。按事先标注，正确描述连续洗手即可通过粗动作检查；这不是三步顺序理解能力的证明。
- 免洗手卫生的使用物答“Soap”，严格按预登记的免洗液真值记为未通过。若宽松接受“Soap”为清洁液近似名称，完整参考与棋盘格各多一项正确；棋盘格仍比完整参考新增丢失一项猫毛色，没有产生相对收益。结论不依赖这一个用词争议。

## 运行与核验

CPU两项契约验证了冻结规则、特征所有权、原读取器一致性、两互逆片段的源像素与顺序，并完成12次随机视觉前向、72次随机问答重放。随机输出不做能力评分。

GPU93第一次尝试在载入前被RAM门禁拒绝：可用约2.63GiB，门槛3GiB；没有模型载入、视觉或问答。用户释放内存后实测可用约7.38GiB，再以新目录提交GPU94；没有降低门槛、覆盖失败证据或改CPU证明。

成功轮实际仅一次模型载入：12次视觉前向、72次问答、587次语言前向、497个生成Token；含载入约33.78秒，峰allocated约3.260GiB、reserved约3.582GiB。保持FP32 IEEE/math、GDN64、主256/问答512、每答最多24Token、360秒watchdog；RAM≥3GiB/GPU空闲≥5.5GiB/转换余量≥2GiB不变。

RGB画布3,538,944B；外部张量保守相加1,780,800B，包含额外复制/投影/匹配的工作估计6,238,336B，低于16MiB登记上限。后者不是实测进程RSS；主缓存23,470,080B与指纹临时2MiB另计。原始视频、模型、环境和凭据不上传或备份。

独立审计覆盖135个源文件SHA、CPU/GPU输入布局与像素、资源门禁、冻结源码、逆序两例的视觉特征逐位身份、候选48Token/来源范围、问答主状态与银行隔离，以及72条原回答的逐题分析。人工自由回答的理由单独存档，没有只挑成功案例。

## 对当前路线的决定

停止围绕这一个猫毛色反复微调几何掩码；保留棋盘格为失败边界明确的候选，不设为默认，也不把它接进整片森林后再期待长程效果自动变好。

下一步回到“保存与取回分开验证”：先用少量未压缩单事件检查，找到两种都能正确读取的事件，固定下来；再比较旧证据单独读取与混入近期证据后的表现。若单独正确、混合错误，优先验证按问题选择旧节点、送入独立问答上下文是否有效。若单独就错，先定位输入与基础读取，不再用它评价长程记忆。人工指定节点只能用于诊断，不冒充自动检索。

对架构学习而言，这轮的成果是明确了一个边界：**有界存储、保留范围、几何覆盖和事实可读性，是四件需要分别验证的事。** 现在已有的混合状态续接、独立问答和有界森林机制继续保留；能力改进仍需新的明确对照支持。
