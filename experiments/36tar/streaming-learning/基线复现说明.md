# 最小基线复现和协作入口

接续前先读 `实验总纲.md`、`架构设计.md`。结果解释见 `基线结果与下一步.md`。当前模型源码完整保留固定仓库版本；扩展入口只有 `code/qwen35-streaming/scripts/baseline.py`。

## 目录与资源

- `.venv` 为当前本机独立环境，不复制到同学电脑或集群。
- `models/Qwen3.5-0.8B` 为本地固定官方权重，不提交 GitHub；模型 revision 与下载清单在总纲/模型目录。
- `datasets/baseline_synthetic` 是本轮 11 KB 左右的合成素材，manifest 保存哈希；需要新素材时用新目录，不覆盖它。
- `reference` 是来源快照，`code` 是工作副本；当前不是正式 Git checkout。
- `runs` 每个 run_id 只能创建一次，含独立 provenance/status/summary/error。
- `scripts/run_baseline.py` 为带 600 秒上限的启动器；GPU 必须引用已完成的相同输入/适配/源码预检，输出每例最多 16 Token、单 GPU、无训练。

## 本机命令（PowerShell）

命令中的 run_id 为示例，已存在时自行换新名称。无需激活旧环境；从项目目录运行。CPU、预检完成后再申请 GPU。

```powershell
Set-Location -LiteralPath 'E:\VIT Model'
$baselinePython = 'E:\VIT Model\.venv\Scripts\python.exe'
& $baselinePython scripts/run_baseline.py --stage cpu --out runs/reproduce_cpu_01
& $baselinePython scripts/run_baseline.py --stage preflight --repair-video-positions --out runs/reproduce_preflight_01
& $baselinePython scripts/run_baseline.py --stage gpu --repair-video-positions --preflight runs/reproduce_preflight_01 --out runs/reproduce_gpu_01
```

第三步重跑全部 5 例。如仅重跑视频，追加 `--only-video`。正常结果是文字 4、图片 red、视频 red/green/blue；生成原始字符串可能带空格/换行，JSON 保留原样。

素材不存在时先生成到一个新目录，再在预检和 GPU 两步都传相同的 `--assets` 路径：

```powershell
& $baselinePython scripts/run_baseline.py --stage assets --assets datasets/synthetic_new_01 --out runs/reproduce_assets_01
```

资产阶段要求目标素材目录不存在，以免覆盖他人或旧运行素材。GPU 若超时，启动器终止子进程并记录 watchdog_status；不能把未完成 status 当作通过。

## 重新建立环境

在新机器新目录使用 Python 3.12（本轮测试版本），创建独立 venv。仓库作者推荐 3.11，若用 3.11 必须再跑 CPU/接口预检。当前 Windows+CUDA126 的完整依赖锁为 `code/qwen35-streaming/requirements-baseline.lock.txt`；它不能保证别的平台 CUDA/驱动自动兼容。

先按 [PyTorch 官方固定版本说明](https://pytorch.org/get-started/previous-versions/) 安装适配目标驱动的 torch 2.10.0 / torchvision 0.25.0，再安装仓库 requirements 与 av 16.1.0；核对完整 lock、pip check、CUDA、原三项测试。不要直接用旧 STC 环境或覆盖同学环境。基线不要求安装 DeltaNet 快算子。

权重下载脚本为 `scripts/download_baseline_model.ps1`，读取固定版本、必要文件、大小和 SHA 清单，不含凭据；目前该脚本适用于 Windows。离线运行只读本地模型；在其他机器必须先自行下载同一 revision，并提供 `--model-dir`。镜像只是传输来源，文件真实性依据固定 revision 元数据和权重哈希核验。

## 后续提交的边界

用户要求各自在自己的分支保存修改，最终合并 main。真正上传前先获取远端最新 main，在新的正式 checkout 建个人分支；把新增入口、依赖说明、脱敏小型结果迁入，核对原模型改动与许可证，再提交 PR。不能把当前没有 Git 元数据的工作副本说成已建分支、已上传。

不要上传 `.venv`、`models`、缓存、原视频数据、凭据或整目录 runs。精选合成样例的文本 manifest 与 JSON/短日志即可；交接备份目前也只包含素材 manifest，素材可用 assets 阶段重建。公开报告需将绝对本机路径改成项目相对路径，删除不必要的用户名、SSH 目标和历史项目路径；原本地证据保留用于复核。

只把真正运行过的结果写进报告，区分第一次失败与带输入兼容适配的重跑。任何模型结构或缓存修正另立清晰提交，不能混入原基线后声称原生多 Token 续接已通过。
