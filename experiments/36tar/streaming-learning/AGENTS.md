# 本项目的持续记录规则

开始工作、接续对话、上下文压缩后，先读 `实验总纲.md`，再读 `架构设计.md`。
用户要求持续维护总纲；每次关键决定、文件修改、验证完成、失败或停工前更新总纲。
总纲是唯一进度主记录，其他文件不维护相互冲突的完成状态。不要声称能在未运行时持续监控。
区分：计划、源码检查、真实运行、能力证据。历史项目记录不能冒充本次实验结果。
默认先完成最小架构学习实验，训练、压缩、榜单优化不是默认必经步骤。
新实验独立目录和环境；旧 STC / 数学 SFT-GRPO 项目只读参考。不覆盖同学的文件。
本地与集群操作分别记录；无远程输出就不得宣称已部署。不得记录凭据。
更换助手模型后继续使用同一总纲，不重新选题。提交 GPU 前列明预算并做接口预检。
交接备份仅包含本项目文档、代码、配置和小型证据，排除权重、数据、环境和密钥。
GitHub 协作：用户要求各自在自己的分支保存修改，完成后通过 PR 合并到 main；不直接向 main 推送。上传前核验当前远端和协作权限，不覆盖同学文件。
