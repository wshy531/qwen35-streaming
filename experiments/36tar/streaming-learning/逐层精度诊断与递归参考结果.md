# S4-A后续：两个候选未通过真实GPU

2026-10-09固定实验事实；持续进度以`实验总纲.md`为准。预登记见`逐层精度诊断方案.md`，原始S4结果见`混合状态续接结果与复现.md`。本轮两次GPU各在预检后执行，没有改变既有数值门槛。

## 1. 归一化精度假设：GPU对照没有支持修复

两段原文字输入保持与上一轮完全相同，分别20Token/2→18和98Token/63→1→34。四组对照：原BF16归一化两组、仅q/k归一化FP32两组；权重始终BF16，实验上下文结束后恢复原函数。

| 输入 | 原路径max/mean/RMS | 归一化FP32 max/mean/RMS | 结果 |
|---|---|---|---|
| 短文字 | 0.5000 / 0.04166 / 0.05876 | 0.53906 / 0.04330 / 0.05956 | 两者都失败 |
| 长文字 | 0.6250 / 0.03386 / 0.04607 | 1.0000 / 0.03365 / 0.04609 | 两者都失败 |

第一层原路径的qkv投影、a/b、卷积后的q/k/v、g/beta、q/k L2归一化结果全部逐位相同。最早非零差在递归核心：短文字仅4/40960元素不同、最大1.907e-6；长文字5/200704元素、最大7.629e-6。经过门控归一化、输出投影、残差与后续层，最终logits差明显变大。这里只确定了最早被观测的差异和后续传播，没有证明所有GPU差异来自同一个原因。

这修正了上轮CPU线索的适用范围：CPU随机BF16归一化存在形状相关差异，但它不是这两条GPU原路径第一层的差异来源。FP32归一化不能据此作为已验证修复；候选整段相对原BF16整段也发生max0.5/0.625偏移，最后argmax同，但不能当作无行为变化。

记录`s4_layers_preflight_20261009_01/02`、`s4_layers_gpu_20261009_01`；第一版预检后补了微型模型hook接口检查，第二版用于GPU，每版脚本独立快照。GPU8.316秒含加载，allocated峰值2.4381GiB/reserved2.6738GiB。诊断status completed仅表示统计完成，candidate_two_groups_passed=false；不表示数值验收通过。

## 2. 逐Token递归：首层CPU成功不能推广到整机GPU

在相同真实第一层权重/20Token、2→18布局下，CPU原BF16块算法核心3个元素不同，输出7个元素不同；把整段和分块都改为逐Token递归后，核心、门控归一化、输出、卷积和递归状态逐位一致。两种算法的整段输出本身仍有7个元素差异/max0.00012207。FP32时两种算法的分块输出最大差都约1.79e-7。

这是只读首层、单一固定样例的证据，不能直接推广为所有输入/整个模型/GPU。记录`s4_recurrence_cpu_20261009_01`，约1.998秒。

基于此添加默认关闭的`text_config.streaming_recurrent_reference`实验开关，使用已有torch逐Token递归核心，原默认块算法保留。开关不新增参数、不改权重、不改变归一化精度；这是一条较慢的正确性参考路线，不是已验证性能优化。

CPU共29项：原适配3、默认混合状态12、候选相同契约12、参数/配置checkpoint2，全部通过。包含候选的卷积/64Token边界、多seed、因果、4轴视觉后文本、fork/reset/容量和保存重载。CPU01后仅调整GPU峰值采集起点，为严格匹配全源码哈希再次做CPU02；两个CPU记录均保留，不称新增覆盖。

## 4. 复现和下一项

原默认模型/基线保留，实验开关默认关闭，未改成主推荐路径。若复现候选，在根目录使用新run：

```powershell
.\.venv\Scripts\python.exe scripts\run_mixed_state.py --stage cpu --out runs\recurrent_cpu_new --recurrent-reference
.\.venv\Scripts\python.exe scripts\run_mixed_state.py --stage preflight --out runs\recurrent_preflight_new --recurrent-reference
.\.venv\Scripts\python.exe scripts\run_mixed_state.py --stage gpu --out runs\recurrent_gpu_new --cpu-check runs\recurrent_cpu_new --preflight runs\recurrent_preflight_new --recurrent-reference
```

这只是复现入口，不能据此自动追加GPU重复失败。没有开关时仍走原默认路线；启动器拒绝预检/CPU与GPU模式不一致。固定四组定位入口为`scripts/run_precision_layers.py`，首层CPU入口为S4仓库中的`scripts.precision_recurrence_cpu`。

此前模型及两个已改脚本的精确历史版本保存在`s4_before_recurrent_20261009_01`，按历史SHA复核；CPU01峰值统计调整前的GPU脚本另存快照。历史run不能用当前源码哈希冒充原样复现。轻量交接包含这些版本和统计，不含模型权重或完整激活。

下一项拟先建立高精度整语言模型参考，并分别对GPU门控归一化、输出投影/矩阵内核、递归核心计算做对照；只做能区分具体假设的实验，先CPU/接口预检与内存预算，再列新的小规模GPU方案。高精度整模型尚未运行，也不能把“BF16会舍入”当作已经排除全部接口bug。
