# 同帧读取与无动物回答定位结果

2026-10-14阶段快照，持续进度只查《实验总纲.md》。综合汇报未改。

**本段已完成16个真实回答。结论是：在这四个固定帧对上，完整特征保存和读取没有新增可观察损失；但“允许回答没有动物”的新问法退化为全部答none，不能采用。**

## 为什么需要这个对照

第二段视频验收发现，画面只有片头/片尾文字时，模型仍然说有狗。此前不能区分三种可能：原模型就会这样答、我们的特征读取丢了信息、或者问题先假设“有动物”而诱导回答。

因此这次固定画面和权重，交叉比较两条路径与两种问法。它的作用是定位问题，避免为了修错误去改不相关的森林或压缩算法。

开始前fresh fetch发现协作方已新增文档PR #4，main推进到`6ed58af`。旧基线保护在切分支前拒绝了过期计划；核对它只有README和快照文档改动后，从最新main建立`36tar/readout-grounding`。

这项修复改善的是低采样率来源稳定性；下面的读取诊断是另一条问题线，不把两者混成一个识别能力收益。

## 画面、路径与问法怎样控制

四例各使用两张真实采样画面，没有拼接新时间轴：

| 案例 | 原视频采样时间 | GPU前看图固定的真值 |
|---|---|---|
| 狗 | 20、22秒 | 浅色狗 |
| 猫 | 0、约1秒 | 黑白猫 |
| 片头 | 0、2秒 | 图形和文字，无动物 |
| 片尾 | 40、42秒 | 片尾文字，无动物 |

这些都是已见来源的小案例，不能叫新来源泛化。原帧ID/PTS/视频及画布SHA记录在证明中，文件名和人工标签没有送进模型提示。

两条路径：

1. **官方原实现**：将同一帧对交给完整视觉/语言模型，从新上下文回答。
2. **当前完整特征读取**：将帧对成功写入主会话，捕获48个完整投影Token；重置主状态，再用已有`native_context/native_answer`在独立语言上下文读取该节点。没有森林、合并或Token删减。

每条路径都运行以下两种问法，T使用该例固定查询时间：

```text
Name the animal visible at T seconds.

Which animal, if any, is visible at T seconds? Answer none if no animal is visible, or uncertain if the image is unclear.
```

因此共4帧对×2读取路径×2问法=16回答。新问法通过独立诊断直接读取事先指定的节点，绕开当前文件入口的严格语法解析；没有宣称它已成为入口支持的新功能或自动语义检索。

## 真实结果：两条路径都出现相同行为

下表每格中，原模型与特征读取的答案完全相同：

| 实际画面 | 旧问法 | 允许none的新问法 |
|---|---|---|
| 狗 | A dog. | none |
| 猫 | A cat. | none |
| 无动物片头 | A dog. | none |
| 无动物片尾 | A dog. | none |

**旧问法的问题是乱说有动物；新问法的问题是连真动物也不承认。** 对每条路径而言，动物正例从2/2变为0/2，无动物负例从0/2变为2/2。只报“无动物问题改善”会掩盖正例丢失；合并成单个总分也不能说明解决了问题。

所以没有将新问法、拒答门控或新模板接入默认入口，也没有继续增加一批问法来挑成功答案。这轮候选没有达到采用条件。

## 为什么能把问题缩小到读取后的回答行为

CPU预检已经核对8个案例×问法组合：官方整段与成对输入全部Tensor相同，两路径的Token ID、四轴位置、视觉值和首步logits逐位相同；微型随机模型32次相关回答只用于机制检查，不评分。GPU前实际看过8张采样图，并冻结正负例标签。

真实GPU的8组原/特征配对进一步满足：

- 输入Token ID相同。
- 四轴位置相同。
- 视觉特征SHA相同。
- 首步完整logits SHA相同。
- 最终生成Token ID相同。

独立审计还核对148源、模型资产身份、CPU/GPU像素计划、全部16原答/EOS/生成计数、预算和门禁。特征问答不重新视觉编码，也不改主状态、银行或节点；主reset后，保存特征仍用于独立读取。

这些结果支持：**在本轮相同输入条件下，没有证据把额外错误归给完整特征保存/读取适配；原模型本身也出现了对应失败。** 不能推广成所有历史、所有压缩或任意输入都等价，更不能说已经找到了某个注意力头或递归层的问题。

同一问法的两条路径相同，与两种问法之间的比较是不同层次。新问法同时改变了措辞、长度和后续位置（问题后缀由21变41个Token），因此只能评价这整套问法，不能断言具体哪个词造成全部none。

## 参数、代码与资源

独立开发源在`E:/VIT Model/experiments/readout_grounding_v1`：`cases.json`固定素材/问题，`probe.py`运行两路径和预检，`run.py`在导入模型前冻结源码并限制子进程360秒，`方案.md`是事前范围和预算。

原始读取调用`streaming.fair_inputs.whole_inputs`与固定官方模型类；特征路径的关键流程为：

```python
wrapper.feed(first_frame)
wrapper.feed(second_frame)
node = raw(wrapper.inner.bank.current)
wrapper.reset_main()
result = native_answer(model, wrapper.inner.session.builder, [node], question, 24)
```

这里reset只清主会话；节点是另外保存的完整48×1024 FP32投影，`native_answer`仍有语言prefill成本，不是零成本读取。

两独立GPU子进程各载入一次权重，FP32 IEEE/math、greedy、最多24生成、QA上下文768。实际原侧8视觉/24语言/8QA/24生成，特征侧4视觉/40语言/8QA/24生成，合计12视觉/64语言/16QA/48生成，全部EOS。原侧每问重新视觉编码，特征侧每帧对只编码一次后复用两问；生成循环对EOS是否再前向也不同，不能用这些计数直接宣布端到端提速。

峰allocated原3.23322GiB、特征3.23389GiB。RAM至少3GiB、空闲GPU至少5.5GiB、FP32转换余量至少2GiB门禁均通过，没有采用协作脚本1.5GiB的RAM门槛。RGB小画布预算与原解码临时内存区分，原视频解码器和完整原RGB并不包含在小帧包上限内。

原始证据分别在`runs/readout_grounding_cpu_20261014_01`、`readout_grounding_original_gpu_20261014_01`、`readout_grounding_features_gpu_20261014_01`；独立逐题分析在`runs/readout_grounding_audit_20261014_01`。累计本机GPU提交104，本段两次成功真实载入，没有训练、摄像头或集群部署。

## 对下一步的影响

这一步已经完成其定位目标：不能把无动物误答当成森林损失，也不能把添加none提示当成有效修复。主混合状态与完整外部证据的架构可以保留，新增问法暂不采用。

后续若继续做“没有动物时可靠说明没有”的能力改进，需要把正例保留与负例拒答作为同等条件，研究证据驱动的回答协议或训练需求。开放画面描述可以作为另一任务，但不应在本轮结果之外声称已经验证。现阶段不靠扩大记忆、继续调压缩或只统计负例来掩盖回答能力边界。
