# 配对早期记忆：结果与解释

本轮在2026-10-14完成新CPU预检和真实GPU88。使用原FP32权重；新候选只在独立诊断目录。综合汇报不写本轮。

## 为什么做

此前视频中狗重复出现在开头、中间和结尾，模型回答“开头是狗”可能只是猜到末尾主体。本轮把结尾固定为同一段洗手/擦手，开头分别是狗与猫。最近窗口已经没有动物画面，只有保存的旧证据能区分两条输入。

两组各两条：第一组狗源12起4帧、猫源0起4帧；第二组狗16起4帧、猫4起4帧。每条后接clean_hands源6起12帧。总32真实成对帧编码。0..15秒是合成会话时间，原源时间和像素身份另外记录。第二组开头帧与第一组不重叠，但仍是同一批已见视频和相同末段，不能当作独立泛化。

## 先看最关键结果

问题固定为“Name the animal visible at the beginning of the video.”。

| 条件 | 第一组狗开头 | 第一组猫开头 | 第二组狗开头 | 第二组猫开头 |
|---|---|---|---|---|
| 未压缩8对参考，原读取布局 | dog，正确 | cat，正确 | dog，正确 | dog，错误 |
| 未压缩8对参考，统一区间布局 | dog，正确 | cat，正确 | dog，正确 | dog，错误 |
| 192 Token森林，原读取布局 | dog，正确 | cat，正确 | dog，正确 | dog，错误 |
| 192 Token森林，统一区间布局 | dog，正确 | cat，正确 | dog，正确 | dog，错误 |
| 最近4对，仅洗手画面 | dog，猜中 | dog，错误 | dog，猜中 | dog，错误 |

严格成对要求同一组狗/猫两条都正确：未压缩和森林均1/2组，最近窗口0/2组。逐条则前四种都是3/4，最近窗口2/4。两组关联很强，只用于定位，不作通用准确率。

“最近窗口猜中狗”不说明它记住开头。两条最近窗口的输入Token、位置、视觉特征和生成答案逐位一致，实际已没有动物证据。

## 交换旧记忆：第一组回答跟着旧证据变化

两条森林的根跨度一致，都是0–1、2–5、6、7。第一根把两对动物的96个原视觉Token压为48个；后来洗手根深度3。相同末段根的特征逐位相同；原问题文本、时间标签与四轴位置也相同，语言输入差异来自动物旧根的视觉特征。

把第一组狗视频的旧根换成猫旧根，答案从dog变成cat；反向交换则从cat变成dog。交换没有写回主状态或银行。这是本轮最有价值的证据：该组答案确实依赖已经保存并压缩的早期视觉信息，而不是重复末尾动物或题目文字。

第二组交换后仍都答dog。这组猫的两个单独未压缩帧对也都被答成dog，因此它不能支持新的记忆收益结论。所有失败都保留，未通过调问题或替换画面隐藏。

本轮没有触发跨闭组的长期森林合并，只有事件内部合并。因此成功案例说明两对动物压成一个旧根之后仍可读，不说明任意长、多事件合并都有效。前一GPU87的长期合并运行证据继续单独保留。

## 四组诊断发现了什么

针对实际最早根，读取同范围的未压缩/压缩内容，各自单独或加最新一对洗手帧。使用固定问题“Name the animal visible during the first 0.0-3.0 seconds.”。

第一组狗/猫和第二组狗，这四种方式都正确；第二组猫，这四种方式都答dog。固定前两对强制合并的控制也呈相同模式。

所以，本轮没有复现“未压缩正确但压缩错误”或“旧根单独正确但加近期错误”。目前不能据此宣称已定位全部历史失败原因，也没有依据降低默认压缩率或引入训练。

第二组猫的错误在完整未压缩参考里已经存在；在本轮输入与读取条件下，基础可答性是明确限制。这不等于证明原模型在所有分辨率和官方视频调用下都认不出猫。

## 我们尝试的一项读取改动

原方式为每个节点添加时间标签和视觉区块。新packed候选把选中的所有节点放进一个时间区间，只写一次区间标签，视觉Token仍保持来源顺序。

```python
# 视觉位置：source是原帧对编号，first是所选区间的起点
t = offset + source - first
h = offset + original_row
w = offset + original_column
offset += max(8, last - first + 1)
```

在相同来源跨度下，压缩前后时间文字和问题后三轴位置相同。语言第一轴和Token数量仍随压缩改变，没有用padding冒充完全等价。

此候选本轮没有提升正确率，也没有修复第二组猫误识。它作为进一步位置/读取诊断的可选工具保留，默认入口不升级。来源坐标仍是融合Token的启发式位置，mass只用于合并加权，不自动影响语言注意力。

## 实际运行与资源
