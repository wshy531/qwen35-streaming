# S3 有限压力与 reset：结果、限制及复现

进度以 `实验总纲.md` 为唯一主记录。本报告对应本机 2026-10-09 的真实运行；未运行集群、摄像头或训练。

## 1. 结论

预登记的**状态与资源判据通过**，但颜色能力检查仅 **81/100**。不能把它称为“长期稳定且视频理解全部通过”。这是一段约39秒的合成视频快速重放，问答仍独立重算4帧窗口，并非模型内部持久流式状态。

原模型源码和权重没有改动。新增应用会话管理和独立实验入口；S1/S2 入口及原结果保留。临时推理 cache 每问答创建/自然释放，reset 清理的是窗口、计数、身份和模型的 `rope_deltas`，不是尚未实现的持久记忆缓存。

## 2. 工作负载与实际验证

运行前方案见 `长运行与重置验收方案.md`。固定官方 Qwen3.5-0.8B、BF16/SDPA、RTX4060 Laptop，torch 原生回退实现；窗口≤4帧/最长边256/1FPS/每2采样帧触发/最多16输出Token。最多1024输入Token，实际105–181。

一次加载权重，先120帧连续视频/60问答，再交替 A（红→蓝）与 B（绿→蓝）20段，每段4帧/2问答；总200采样帧、100问答、20次同一会话对象 reset。另4个空缓存控制 prefill 只建立CPU首步logits参考，没有生成答案。含加载运行38.855秒，600秒watchdog未触发，实际每次输出最多4Token。

| 验证项 | 证据 |
|---|---|
| CPU契约 | 9/9通过（6窗口/采样+3会话/reset） |
| 实际MP4接口预检 | 100窗口、200采样帧、20reset，位置oracle通过 |
| 每问答独立起步 | 100次首轮语言past=0 |
| 临时缓存释放 | 100次问答返回后缓存弱引用存活数=0；控制前向同样释放 |
| reset清理 | 20次窗口/计数/身份重置，rope_deltas清空；首次真实旧delta=-112 |
| reset输入/数值 | 40次与4个新窗口参考输入完全一致，完整首步logits逐位相同，最大差0 |
| 容量 | 窗口像素≤786,432字节（0.75MiB） |
| 启动门禁 | 改用另一资产目录而复用旧预检，在创建run前拒绝，无额外GPU运行 |

CPU首次检查后修正实验记录字段为 `total_tensor_bytes`，第二次CPU检查固定最终代码；两次CPU均9/9，不是模型失败重跑。所有运行目录独立保留。

## 3. 资源测量

每次问答函数返回后同步GPU，临时输入/输出自然释放后采样。未逐问调用 `gc.collect` 或 `empty_cache`；只保存小型CPU记录与4份CPU控制向量。Windows private是实时私有提交量，RSS是实时驻留工作集，均不采用历史peak字段。

第11–100问答为预登记稳态区间：

| 指标 | 最小–最大 | 首10点→末10点中位数 | 判据 |
|---|---|---|---|
| GPU allocated | 1,746,103,808字节，跨度0 | 增长0 | 跨度/中位数增长≤2MiB，通过 |
| GPU reserved | 1,874,853,888字节，跨度0 | 增长0 | 分配器保留量，单独记录 |
| 进程private | 5,015,212,032–5,031,112,704字节 | 增长15,822,848字节（15.09MiB） | ≤64MiB，通过 |
| 进程RSS | 59,535,360–1,790,222,336字节 | 减少约1.55GiB | 无超过64MiB的增长；完整波动保留 |

RSS在中段大幅下降，因此不能描述为“所有内存指标平稳”。没有采样Windows工作集裁剪/分页原因，不能凭RSS下降断言模型释放了相应内存；private没有对应大幅下降。现有证据只支持此次有限负载内未超过预登记增长门槛，仍需较长时间和真实输入验证。

问答峰值allocated 1.6743GiB/reserved 1.7461GiB。第11–100问答生成及采样钩子耗时中位数0.3132秒；完整logits复制、weakref/缓存形状测量带来额外观测开销，不与S2普通生成时间直接作速度优劣比较。视频不按PTS等待，200帧不代表真实等待200秒。

## 4. 能力问题与单独时间戳对照

| 子序列 | 正确数 |
|---|---|
| 连续120帧 | 41/60 |
| reset A | 20/20 |
| reset B | 20/20 |
| 总计 | 81/100 |

连续序列按末帧颜色：红12/15、蓝15/15、绿3/15、黄11/15。19个错误不是格式误判，包含green→blue、yellow→green、red→white，原答案逐项保存。它们在空past起步的独立窗口发生，不能直接归因于旧cache污染。

问题3与7的4帧像素SHA完全相同，时间从[2,3,4,5]秒变为[10,11,12,13]秒、输入从177变为179Token，回答green→blue。为诊断输入表达，追加**事后选择**的4个错误（7/16/17/59）成对测试，共8问答；保持像素、帧顺序、问题、权重和生成配置，只把原全局时间换为窗口起点为0的局部时间。CPU预检确认原输入指纹与100问答记录相同、成对像素相同、位置oracle通过，然后独立GPU运行，最多16输出Token/600秒。

| 原问题 | 预期 | 原时间答案 | 窗口相对时间答案 |
|---|---|---|---|
| 7 | green | blue | blue |
| 16 | yellow | green | yellow |
| 17 | red | white | red |
| 59 | green | blue | blue |

4个原错误全部复现，局部时间2/4正确。这个对照支持“时间戳表达影响部分答案”，不支持“改为局部时间就解决末帧理解”，也不能用挑出的4个样例宣称总体准确率提高。时间戳文本变化还会改变Token数/位置，这里没有进一步分离其内部机制。保持默认真实PTS和100次主结果，不为提高数字静默修改协议。
