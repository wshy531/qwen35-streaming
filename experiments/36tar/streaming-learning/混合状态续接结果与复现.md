# S4-A：续接结构修正与低精度失败记录

本文记录2026-10-09这次实验，持续进度仅以`实验总纲.md`为准。方案在运行前写入`混合状态续接验收方案.md`。

## 这次实际解决了什么

Qwen3.5有两类语言层：6层普通注意力保存历史K/V；18层GatedDeltaNet还保存短卷积状态和递归矩阵。可以把它们理解成“历史索引、最近几步的局部信息、持续更新的记忆”。增量输入必须一起续接这四类张量，仅保存KV不够。

原代码把续接限定为一次一个Token。一次追加多Token时，它会重新建立卷积状态，并把递归初始状态设为空，导致前一块的记忆没有被正确带入。本分支修正这个条件，多Token使用现有torch卷积update和带历史initial_state的块算法，单Token路径保持原行为；没有新增参数或训练。

新增HybridSequence管理已见Token数和下一个RoPE坐标，避免视觉位置压缩后仍按Token总数续写文本。fork复制全部真实状态，但共享权重；提问分支的计算不会写回主状态。reset清四类缓存、两个位置计数和模型rope_deltas。上限256Token是拒绝继续追加，不是自动剪掉旧KV。

工作区为`E:\VIT Model\code\qwen35-streaming-s4`，分支`36tar/s4-mixed-state`；起点main/HEAD实查为`61e8de673fe9abb7281f803c1d1c94dc65f6a064`。旧基线目录、只读快照和同学文件保留。尚未commit/push/PR；Git提交身份未配置，36tar远端写权限未核验。

## 失败后的CPU定位

只读真实第一层约20.11MiB权重和20个词向量，用相同2→18布局做FP32/BF16检查，不再次运行GPU。FP32第一层输出最大差1.79e-7，BF16第一层约0.00012207，且投影/卷积输出相同；这一层未复现整模型的大误差。

独立随机算子检查发现：BF16下，同一批q/k做整段L2归一化与先切片再归一化，最大差0.00390625；FP32归一化逐位相同。原BF16随机块算子最终状态差0.00898087，而先FP32归一化/计算的控制对照约1.79e-7。它说明本机CPU低精度实现存在形状相关误差，支持把归一化精度作为下一项诊断；CPU结果不能直接确定GPU整模型根因。控制对照是事后分析，未替换GPU主结果或修改候选模型精度路径。

两次定位记录分别为`s4_precision_cpu_20261009_01/02`；第二次增加了归一化形状检查和FP32控制。第一版脚本哈希保留在第一run，最终脚本与第二run哈希匹配，不能声称第一run由最终脚本原样复现。

## 复现与后续边界

在项目根目录，输出必须使用新run名称：

```powershell
.\.venv\Scripts\python.exe scripts\run_mixed_state.py --stage cpu --out runs\s4_cpu_new
.\.venv\Scripts\python.exe scripts\run_mixed_state.py --stage preflight --out runs\s4_preflight_new
.\.venv\Scripts\python.exe scripts\run_mixed_state.py --stage gpu --out runs\s4_gpu_new --cpu-check runs\s4_cpu_new --preflight runs\s4_preflight_new
```

这是复现入口，不表示应立即重跑已失败GPU。CPU事后定位可在S4仓库中执行`python -m scripts.precision_diagnostic_cpu --out <新目录> --model-dir <模型目录>`；独立仓库说明见`S4_A.md`。

下一步先做算子/逐层精度定位，区分原BF16归一化、块计算、GPU内核差异；如做FP32内部算子候选，必须同时记录其对整段原模型输出的影响，不能靠修改参考来掩盖偏移。后续GPU单独列预算和预检，保留这次原门槛/失败。
