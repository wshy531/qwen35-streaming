# 新视频历史读取、同末对与早期证据交换验证

本段最重要的结果是：**外部保存的原始视觉特征确实能被模型用于区分新的早期内容；但“先描述，再读文字”会丢掉部分可用信息。上一轮的局部问句候选有局部收益，尚不适合作为统一默认路径。**

## 1．为什么要换新视频

上一轮局部问题＋纯描述在熟悉8题上达到7/8，但不能据此认定换素材也稳定。本轮固定原提示、原标签和读取方式，下载两段此前未参与选词的真实猫/狗视频：先按首两个1fps采样取早期画面，再用狗视频2、3秒的同一帧对作为共同结尾。另加已用过的洗手无动物控制，明确不把它称为新素材。

```text
甲：新狗早期 → 完全相同的狗结尾
乙：新猫早期 → 完全相同的狗结尾
负控制：洗手 → 完全相同的狗结尾
```

以上是受控合成序列，时间重排为0..1与2..3秒。它不是一段自然转场长视频；原帧ID、原PTS、像素哈希另存。新素材也不代表模型预训练未见。输入在真实模型运行前人工查看并冻结标签，没有根据模型答案挑成功片段。

来源为[Dog whimpering](https://commons.wikimedia.org/wiki/File:Dog_whimpering.webm)（Андрей Романенко）与[Кішка вмивається](https://commons.wikimedia.org/wiki/File:%D0%9A%D1%96%D1%88%D0%BA%D0%B0_%D0%B2%D0%BC%D0%B8%D0%B2%D0%B0%D1%94%D1%82%D1%8C%D1%81%D1%8F.webm)（Сарапулов），Commons元数据均标CC BY-SA 4.0。原字节及官方SHA1/本地SHA256已核验，总57,669,565字节。音频不参与；解码、采样、等比缩小与合成时间属于本地处理。媒体不上传仓库或交接ZIP。

## 2．比较了什么

三条路径收到同一份由严格时间索引选中的完整48Token帧对：

- 直接读取：原时间问题直接读取保存的视觉特征。
- 原文字桥：中性视觉描述→原时间问题＋区间包装→固定文字回答器。
- 候选文字桥：共用同一中性描述→局部问题＋纯描述→相同文字回答器。

正常的局部问题只能在索引成功后产生，原问题、时间、来源区间与特征哈希一直保留。查询没有重做视觉编码，没有训练、压缩、森林修改或新一轮提示搜索。这里的直接参照是同一完整目标特征路径，不是原官方默认高分辨率整段视频基线。

## 3．逐题真实结果

| 问题位置 | 真值 | 直接特征 | 原文字桥 | 候选文字桥 |
| --- | --- | --- | --- | --- |
| 新狗开头 | dog | A dog. | none | none |
| 狗序列共同结尾 | dog | A dog. | none | none |
| 新猫开头 | cat | A cat. | bird | cat |
| 猫序列共同结尾 | dog | A dog. | none | none |
| 熟悉洗手负控制 | none | A dog | none | none |
| 洗手序列共同结尾 | dog | A dog. | none | none |

按事前固定短答案别名：直接5/6，原文字桥1/6，候选2/6。候选相对原桥纠正新猫1题、损失0题；不因两条桥分数低就否定它的这一纠正，也不把这一次纠正泛化为统一优越。

三个结尾是同一份狗帧对，不能当三段独立视频的重复验证。按4个不同完整帧对（狗早期、狗末对、猫早期、洗手）仅作描述性去重：直接3/4，原桥1/4，候选2/4。新猫/狗早期必须两题都答对的严格配对终点：直接通过，原桥与候选均未通过。两桥格式均6/6合规，格式正确没有解决事实错误。

## 4．失败究竟发生在哪里

**狗：中性描述漏掉了问题需要的信息。** 狗在栅栏后。直接问保存的视觉特征，能答dog；同样的特征用于描述时，却只得到“房子、花园、树”，末对得到“铁丝网、花园、树、房子”。描述没有提狗，两条文字桥都答none。

> 短描述没有提到动物，不等于画面明确没有动物。

这不是容量重置忘记历史：目标特征仍在，索引选对，直接路径能读出狗；本轮也没压缩，不能怪森林合并。关键损失发生在“视觉特征→自由文字描述”这一步，文字读取器随后又把遗漏变成了否定。

**猫：局部读取仍有收益，但描述本身也不可靠。** 中性描述同时写猫和“落在猫背上的小鸟”（人工输入检查未见鸟）。原文字桥挑了bird，候选选cat，最终主体得到纠正。但答对猫不说明这段描述的其余细节都正确。

**洗手：直接路径仍会误报。** 原始视觉特征直接答dog，描述则写洗手，两条文字桥都答none。这是文字路径仍值得保留的具体例子，也说明不能在看完答案后临时宣布“以后全部选直接路径”或“全部选文字路径”。

## 5．交换和移除证据，证明了什么

同末对的甲、乙各问最早0.5秒。直接路径分别答dog/cat。然后只交换早期完整特征，末对、问题和时间位置不变：甲的早期换成猫后答cat；乙换成狗后答dog。两向都正确，且交换后输入IDs、视觉值/位置、首logits和生成，精确复现另一序列对应早期条件。

因此，在本受控条件下，直接路径的不同答案确实依赖交给它的早期证据，不能靠相同结尾区分。候选文字桥交换后为cat/none，仍未达到两向都正确，不能宣称它已经可靠利用所有早期记忆。

移除早期节点时，三条正式请求都被时间索引拒绝，零问答调用；这是系统边界，不计模型准确率，也不伪造none。另对甲、乙各做一次明确标记的forced_tail人工模型诊断：绕过路由，故意只交共同末对。直接均dog、两种文字读取均none；两组输入IDs、首logits及生成完全相同。它只说明这份共同末对无法区分两种原开头，**不是正常候选路径的回答或得分**。

## 6．运行、资源与复现

CPU7合同和完整40随机模型QA通过，只证明接口；GPU113真实1次load、4视觉/301语言前向、40模型调用、253生成Token、全部EOS，无输出预算截断。30最终输出分为18正常、6交换、6未评分的强制末对诊断。峰allocated3.2316GiB，峰reserved3.3789GiB；本次载入与重放约20.88秒，不据此宣称加速。

事前预算1load/4vision/40QA/960生成/1100语言/360秒，24输出Token，FP32 IEEE/math greedy，主256/视觉768/文字384。RAM≥3GiB、GPUfree≥5.5GiB、转换≥2GiB均实际核验；外部保守特征工作2,771,328字节。180源、权重/素材SHA、CPU/GPU像素身份、共用描述、所有提示/日志/干预身份、13零前向拒绝、主状态/银行/索引/节点隔离通过独立审计。

源码位于独立 `experiments/readout_transfer_v1`：`condition_nodes`只在显式干预中交换早期；`route`沿用严格时间语法；`replay`把forced_tail与candidate_bridge分开记录；`reader`沿用固定结构化R。源银行中的完整投影在主reset后保留，查询时不再次视觉编码。全部失败保留。

## 7．下一步如何调整

本轮暂不把文字描述升级为统一证据，也不再用更多提示试图掩盖狗的遗漏。应保留原始目标特征作为直接读取依据，将中性文字描述作为可查看的辅助材料；目前两者冲突时，没有经验证的自动裁决规则。

下一段最值得做一个小而具体的读取结构对照：在同一目标节点、同一问题下，比较直接视觉回答与“同时保留视觉特征并附描述”的独立问答上下文，原文字桥作参照。它能检验保留直接视觉通道是否减少文字瓶颈，同时保留洗手负控制检查是否重新引入误报；不应自动在几条路径里挑事后正确答案。先固定新案例/接口/预算，再决定是否值得接入可选演示。

长期森林、语义检索、训练、默认升级仍需要各自证据。当前直接路径通过新早期与交换对照，是本段实质成果；文字候选只修复一题且暴露新的遗漏边界，也是应该保留的结论。持续进度只更新实验总纲，旧综合汇报未改。
