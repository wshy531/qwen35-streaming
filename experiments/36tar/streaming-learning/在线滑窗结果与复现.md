# S2 在线滑窗：本轮事实与复现

日期：2026-10-09。持续进度以 `实验总纲.md` 为准，本文件固定本次验证结果。设计与验收条件见 `在线滑窗设计与验收.md`。

## 得到什么

在原 Qwen3.5-0.8B 上实现应用层顺序视频重放、PTS 抽帧、4 帧近期窗口、每 2 个采样帧触发一次问答。6 项 CPU 契约测试通过；12 个窗口的处理器/位置预检通过；本机一次 GPU 运行的 12 次末帧颜色回答全部符合预期。模型和原始来源文件未改，不训练，不把 KV/记忆森林作为新增机制。

它已经能在输入不断推进时针对当前窗口回答；每次仍重算窗口视觉和语言前缀，没有跨问答持久模型记忆。离开窗口的早期帧不可再通过本模块访问，不能声称拥有长期视频记忆或模型级增量推理。当前仅同步文件重放，没有摄像头、异步队列或实时等待。

## 实际时间轴

两条视频均为 12 帧、256×256、1 FPS 的自生成色块，开头同为红色。每种颜色连续两帧；使用无 B 帧的逐帧编码和固定无损量化，避免不同后缀影响共同前缀的解码像素。答案只问“当前窗口的最后一帧是什么颜色”。下面是实际完整答案去除空白后的记录。

| 回答截至（秒） | 窗口帧编号（从 0 开始） | 视频 A 预期 / 实际 | 视频 B 预期 / 实际 | 时间块标记（秒） |
|---:|---|---|---|---|
| 1 | 0,1 | red / red | red / red | 0.5 |
| 3 | 0,1,2,3 | blue / blue | green / green | 0.5,2.5 |
| 5 | 2,3,4,5 | green / green | blue / blue | 2.5,4.5 |
| 7 | 4,5,6,7 | yellow / yellow | yellow / yellow | 4.5,6.5 |
| 9 | 6,7,8,9 | red / red | red / red | 6.5,8.5 |
| 11 | 8,9,10,11 | blue / blue | green / green | 8.5,10.5 |

1 秒处两视频实际模型输入指纹完全相同，答案都是 red。3 秒处才出现分叉对应的 blue/green。第 6 帧以后，窗口明确淘汰早期帧。生成器检查证明触发问答时应用还未取得下一帧；真实运行每条记录的 delivered_decode_count 等于当前末帧编号+1，窗口时间没有随滑动归零。

这是应用/模型输入的因果边界证据。编解码器可能为压缩参考或缓冲在内部预读，本实现不保证它的底层读取完全没有未来数据；本阶段保证未来帧不交付应用窗口或模型。文件重放没有按 PTS 睡眠，因此“截至 11 秒”是视频时刻，不是已等待 11 秒。

12 个答案只是这些合成样例的当前颜色检查，不是公开榜单准确率。并未测试窗口外回忆、自然视频理解、完整事件排序、复杂场景、长时间稳定性或多人同时输入。

## CPU 和输入证据

`window_cpu_20261009_02` 的 6 项测试包括：问答触发时不取得下一帧；非法 append 不改状态；像素复制/只读与 reset；非均匀 PTS 下的因果采样和掉帧；100 帧后容量仍受限；共同前缀不受不同未来影响。

`window_preflight_20261009_01` 中，12 个 MP4 窗口的 input_ids、attention_mask、mm_token_type_ids、pixel_values_videos、video_grid_thw 与原 processor 全部逐张量精确相同。额外检查 1/2/3/4 帧，奇数帧只重复已知末帧来完成两帧时间 patch；非均匀已知 PTS `[0.2,1.4,3.9]` 渲染时间块为 `0.8/3.9`，没有假造未来时间。

因原 processor 用 frame_index/fps 推算时间，我们调用相同 video_processor 后按原格式写入真实 PTS 的时间块均值，允许以后接入非均匀采样。仍采用 S1 验证过的显式 position_ids 兼容适配，原模型和 site-packages 没有修改。

两帧窗口为 64 视觉 Token、总输入 105 Token；四帧为 128 视觉 Token，总输入 177–178 Token。后面的时间戳字符 Token 化会使总数轻微变化。每次生成实际输出 4 Token（含模板结束/换行），上限保持 16。

## 运行成本与状态

设备/固定权重/版本同 S1：本机 RTX 4060 Laptop、BF16、SDPA、Transformers 5.3.0、torch 2.10.0+cu126；未安装 FLA/causal-conv1d 专用快算子，DeltaNet 使用 torch 的 GPU 原生回退实现。

| 量 | 本次记录 | 能说明什么 |
|---|---|---|
| 窗口像素 | 最大 786,432 字节 = 0.75 MiB | deque 中 4 帧 RGB 受限；不代表所有系统 RAM |
| GPU allocated 峰值 | 1.6742 GiB | 本次小输入推理分配峰值 |
| GPU reserved 峰值 | 1.7461 GiB | 分配器保留量，区别于活跃 tensor |
| 第一例 generation | 0.714 秒 | 包含初始算子/设备准备影响 |
| 之后 11 例 generation | 0.228–0.277 秒，中位数 0.257 秒 | 观察值，未做正式性能重复实验 |
| 视觉 CUDA event 区间中位数 | 10.38 ms | 之后 11 例视觉模块时间区间 |
| 语言 prefill 区间中位数 | 143.29 ms | 同上，语言读取当前完整窗口 |
| 语言 decode 区间中位数 | 89.22 ms | 同上，所有后续语言调用区间之和 |

generation 是 generate 调用的墙钟时间，不包括 CPU 解码/缩图、processor/位置/输入指纹和传输。每例也保存这些独立阶段的时间。CUDA event 记录模块前后区间，可能包括 CPU 发射造成的 GPU 等待；trace hooks 和状态采集也有额外开销，不声称是纯硬件计算量，不能和墙钟简单混加，也不是严格首 Token 延迟。单次短运行没有误差条、摄像头接入和长队列，不能据此承诺实时 FPS。

每次视觉模块调用一次；语言首轮 past 长度为 0，接着逐 Token decode。问答之间未传入旧 cache，模型对象 rope_deltas 重新构建并释放。末次 178 Token prefill 的原生缓存约 21,946,368 字节，其中 K/V 合计 2,187,264，卷积 884,736，递归 18,874,368；K/V 只在 6 层，卷积/递归各在 18 层。这个分布再次说明，Qwen 缓存不能只用普通 Transformer KV 公式描述。

按这组样例，语言前缀读取和 decode 比视觉编码耗时明显更多。它支持下一步重点研究语言混合状态的正确续接，不支持立刻选择 ViT 内部缓存、Token 压缩或记忆森林。0.8B、短窗口和回退算子下的判断，需要用更长输入/自然视频再核验。

## 代码与复现

新增代码：`streaming/window.py`、`streaming/inputs.py`、`scripts/window_experiment.py`、`tests/test_stream_window.py`；项目启动器 `scripts/run_window.py`。工作副本中原 15 个快照文件仍逐字节相同，S1 原入口也未改。

本机 PowerShell，从项目目录执行，run_id 已存在时换一个新的。素材已保存在本项目；新机器/交接包需要先 assets 阶段生成到新目录，并在后续传同一 `--assets`。

```powershell
Set-Location -LiteralPath 'E:\VIT Model'
$windowPython = 'E:\VIT Model\.venv\Scripts\python.exe'
& $windowPython scripts/run_window.py --stage cpu --out runs/replay_cpu_01
& $windowPython scripts/run_window.py --stage preflight --out runs/replay_preflight_01
& $windowPython scripts/run_window.py --stage gpu --cpu-check runs/replay_cpu_01 --preflight runs/replay_preflight_01 --out runs/replay_gpu_01
```

没有素材时先运行：

```powershell
& $windowPython scripts/run_window.py --stage assets --assets datasets/window_new_01 --out runs/replay_assets_01
```

相应在上面 preflight/GPU 两步追加 `--assets datasets/window_new_01`。默认 fps/window/every 为 1/4/2；新参数必须重新预检并匹配，预算最多 12 次问答、16 输出 Token/次、600 秒进程上限。启动器核对 CPU/预检通过和代码哈希，GPU 入口核对素材哈希；不能覆盖旧 run 或素材目录。

依赖沿用 `基线复现说明.md`。当前 GPU 实验入口针对附带 manifest 的合成颜色用例，不是任意自然视频 CLI；底层 reader/window/input 模块可以复用，接入自然视频时需要独立评测协议，不能借用合成 colors 作为答案。
